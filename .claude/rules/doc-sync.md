# 文档同步规范

## 1. 文档即代码

改代码的同一次变更必须把受影响文档更新到一致。文档未同步等同变更未完成。

## 2. 变更映射

| 改动 | 必须同步 |
|---|---|
| 需求、范围、验收、阶段 | `docs/PRD.md` |
| 模块、数据模型、机制、依赖方向 | `docs/ARCHITECTURE.md` |
| wire、消息、会话、代理或互操作行为 | `docs/PROTOCOL.md` |
| REST、SSE、Agent、认证或错误契约 | `docs/API.md` |
| 部署、升级、备份、回滚或排障 | `docs/OPERATIONS.md` |
| 信任模型、凭证、正文、权限或审计 | `SECURITY.md` |
| 新技术、模式或长期取舍 | 新增 `docs/adr/NNNN-*.md` |
| 用户可见变更 | `CHANGELOG.md` 未发布段 |
| 项目入口、命令或能力总览 | `README.md` |

## 3. ADR 不可变

- 已接受 ADR 不修改决策正文。
- 决策变化时新增 ADR 取代旧 ADR；旧 ADR 只更新状态和取代链接。
- 编号递增、永久保留、不删除、不复用。

## 4. 单一真源

同一事实只在一处权威描述，其他文档链接引用。PRD 管需求，ARCHITECTURE 管当前实现方式，PROTOCOL 管兼容协议，API 管对外管理契约，ADR 管决策原因，CHANGELOG 管用户可见历史。

## 5. 过程文件边界

实施计划、探索笔记、抓包、兼容对比、临时脚本和过程报告只放 `.tmp/`，不得写入 `docs/` 或提交。`.tmp/实施计划.md` 只保留里程碑，不作为完成证据。
