# 配置文件规范

> 适用于 JRP 自身运行期 YAML 配置。业务代理配置以 SQLite 为真源，不得重新引入配置文件双真源。

## 1. 命名

- 文件名使用 kebab-case，扩展名优先 `.yml`；第三方工具强制名称除外。
- YAML 字段使用 kebab-case；第三方框架固定字段按其规范。
- 环境变量使用大写 snake case，仅承载引导参数或部署注入值。

## 2. 中文注释

- 每个 JRP 自有 YAML 字段上方写简体中文注释，说明用途、范围、默认值和影响。
- 注释独占一行，不写空洞行尾注释。
- 文件头用一至三行中文说明加载组件与用途。

## 3. 真源边界

- 客户端、代理、通知和采集策略属于 SQLite 业务配置，不得同时由 YAML 权威配置。
- 数据目录、SQLite 路径和管理 API 根监听是引导参数；改变后需要重启。
- Taskfile 与 GitHub Actions 是工程配置，不是运行期业务配置，遵循各自上游 Schema。

## 4. 安全

- 任何入库配置、示例、测试夹具都不得包含真实 token、密码、私钥、SMTP 密码、Webhook secret、Cookie 或内网敏感地址。
- 未经当前任务明确要求，不创建 `.env` 或 `.env.example`。
- 配置读取必须校验长度、端口、地址、路径和枚举；错误信息不得回显秘密。
