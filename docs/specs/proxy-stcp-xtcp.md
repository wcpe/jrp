# 功能规格：STCP 与 XTCP 代理及 NAT 打洞

> 状态：草拟 · 关联 PRD：FR-06b · 分支：feature/proxy-stcp-xtcp

## 1. 背景与目标

FR-06b 要求 Core 支持 STCP 与 XTCP 两种代理，包含访客连接与 NAT 打洞。这两种代理的共同点是：被代理服务**不暴露公网入口**，访问必须由获得授权的访客发起。

- **STCP（安全 TCP）**：访客与被代理方都连接到服务端，由服务端在两者之间配对并转发。流量经过服务端，不尝试直连。
- **XTCP（P2P）**：访客与被代理方先通过服务端交换地址与会话材料，然后尝试建立点对点直连；成功后数据优先走直连通道，失败则回落到服务端转发或明确失败。

本规格解决的具体问题是：这两种代理引入了「访客」这一新的参与方与「打洞」这一依赖真实网络行为的机制。与 FR-06a 不同，XTCP 的正确性**无法由单元测试证明**——本地回环与容器网络的行为与真实 NAT 设备差异巨大。因此本规格把「实机验收」作为硬门槛而非补充项。使用者：需要安全内网访问的访客、被代理服务的运维者、Core 代理层。所属阶段：P1。

## 2. 需求

- 支持 STCP 代理：被代理方注册后不占用公网入口；访客凭授权材料发起连接，服务端完成配对与转发。
- 支持 XTCP 代理：访客与被代理方交换候选地址与会话标识后尝试直连；成功走点对点，失败行为可观察且释放临时资源。
- 访客连接必须鉴权：目标存在性、访客获准性、共享密钥派生的材料、时间窗口与重放边界。
- NAT 打洞必须有独立实现的探测策略，不得复用参考实现的策略表。
- 打洞成功与失败都必须可观测：成功有直连事件，失败有明确原因类别与资源回收证据。
- 与 FR-05a / FR-05b / FR-05c 全部传输兼容（直连阶段使用 UDP 承载）。

- 范围内：STCP 与 XTCP 的代理语义、访客鉴权、候选地址交换、JRP 自有 NAT 策略分类、打洞时序、成功/失败处理、资源回收与可观测性。
- 范围外：
  - **「JRP 客户端连接官方 frps」这一反向兼容方向，本轮不做**，本规格不承载任何反向兼容承诺。
  - TCP、UDP、HTTP、HTTPS 代理（FR-06a）。
  - **P2 的 SUDP（FR-18）**：本轮不实现基于 UDP 的安全代理变体。
  - 任何第三方打洞协调服务、STUN/TURN 服务器实现或外部中继基础设施。
  - P3 的数据节点、节点 RPC、选举、分布式锁、共享数据库、租户、RBAC、OIDC。

## 3. 设计

### 3.1 访客模型

- **访客**是经批准后可连接特定 STCP / XTCP 代理的身份，由代理的允许列表与共享密钥共同决定。
- 访客连接提交目标代理名、运行身份、由共享密钥派生的鉴权材料与时间窗口。
- 服务端验证顺序：目标存在 → 访客获准 → 材料有效 → 时间窗口内 → 未重放。
- 失败只返回稳定类别，**不暴露目标是否存在以外的敏感配置**；具体做法是：目标不存在与鉴权失败对外返回相同类别，避免探测枚举。

### 3.2 STCP 时序

时序遵循 `docs/PROTOCOL.md` §8.1：

1. 被代理方在登录成功后注册 STCP 代理，声明代理名与允许访客；服务端**不创建公网入口**。
2. 访客以访客身份连接服务端，提交目标代理与鉴权材料。
3. 服务端校验通过后请求被代理方建立工作连接。
4. 服务端把访客连接与被代理方工作连接配对，进入双向转发。
5. 任一侧关闭即开始排空另一侧，释放配对状态。

设计要点：STCP 不尝试直连，因此其行为与 FR-06a 的 TCP 代理在转发阶段基本一致，差异只在入口形态与访客鉴权。

### 3.3 XTCP 时序

时序遵循 `docs/PROTOCOL.md` §8.2：

1. 访客与被代理方分别向服务端报告候选地址与事务标识。
2. 服务端验证代理权限，协调双方获得匹配的会话材料（同一事务标识、彼此的候选地址集合）。
3. 双方按 JRP 自有探测策略尝试直连并报告结果。
4. 成功后数据优先走点对点通道；失败行为必须可观察且释放临时资源。

关键约束：候选地址交换只在已鉴权的会话内进行，服务端不向未获准的第三方泄露候选地址。

### 3.4 JRP 自有 NAT 策略分类方式

**本规格不复制、不改写参考实现的 NAT 策略表。** JRP 采用自己的分类维度，从「可观测行为」出发而非从「设备行为枚举」出发。分类只用于选择探测参数与解释失败原因，不作为协议字段传递。

JRP 的分类维度（自有表述）：

| 维度 | 取值分类 | 用途 |
|---|---|---|
| 映射稳定性 | 稳定映射 / 变动映射 | 决定候选地址是否可复用、是否需要在探测期间刷新候选 |
| 映射可预测性 | 可预测 / 需探测 | 决定是否可以直接推导候选端口，还是必须先观测实际映射 |
| 过滤严格度 | 宽松 / 严格 | 决定是否需要双向同时探测，以及探测包的持续时长 |
| 地址族可用性 | 仅 IPv4 / 仅 IPv6 / 双栈 | 决定候选集合的构造顺序 |

分类的获得方式：由双方各自在探测过程中根据自身发送与接收结果**自行判定**，并把判定结果作为结果报告的类别标签上报服务端。服务端只做聚合与记录，不替任何一方做判定。

探测策略按上述分类组合选择参数（探测并发度、持续时长、重试次数、是否双向同时发起），参数来自配置快照且可调整。这样设计的原因是：JRP 不需要知道对端是哪种具体 NAT 设备，只需要知道「在这种可观测行为下该用什么参数」。

### 3.5 打洞失败与回落

- 探测在超时上限内未成功即判为失败。
- 失败必须报告类别：候选不可达、映射变动、过滤拒绝、超时、对端未响应。
- 失败后释放全部临时资源：候选状态、探测 goroutine、临时 socket。
- 回落策略：P1 的回落行为由代理配置决定——可配置为「失败即拒绝」或「回落到服务端转发」。无论哪种，都必须可观测且不留悬挂状态。
- 禁止无限重试：重试次数与总时长都有上限。

### 3.6 可观测性

打洞相关的事件必须可观测，且**脱敏**：

- 记录：代理名、事务标识摘要、参与双方的身份标识、候选数量、结果类别、耗时。
- 不记录：完整候选地址（只记地址族与是否来自观测）、共享密钥派生的材料、正文。
- 事件经有界通道交给适配器；慢消费者不得阻塞数据面。

### 3.7 与 ADR 的关系

- Core 模块边界与「Core 只承载数据面能力」遵循 ADR-0002 与 ADR-0003。
- 无中断配置应用遵循 ADR-0005。
- 兼容实现的独立性与固定基线遵循 ADR-0010（取代 ADR-0001）；**尤其不得复用参考仓库的 NAT 策略表或测试组织**，本规格不重复其决策正文。

## 5. 验收标准

正常路径：

- STCP：未获授权访客被拒绝；获授权访客可访问被代理服务，数据双向可达；被代理方不占用公网入口。
- XTCP：候选地址交换在已鉴权会话内完成；打洞成功后数据走点对点通道，服务端可观测到直连建立事件。
- 关闭任一侧后另一侧排空，配对状态与临时资源释放。

边界：

- 时间窗口边界（窗口内、窗口外）行为可判定。
- 重试次数与总时长达到上限后判为失败，不无限重试。
- 候选数量为 1、多个、0 的情况分别被正确处理（0 候选直接判失败并上报）。
- 并发多个打洞事务时互不干扰，事务标识正确隔离。

错误路径：

- 未授权、时间窗口外、重放、目标不存在四类访客鉴权失败返回相同稳定类别，不泄露目标是否存在。
- 打洞失败五种类别均被正确上报，且临时资源（goroutine、socket、候选状态）全部释放。
- 回落策略为「失败即拒绝」时访客收到明确拒绝；为「服务端转发」时数据可达且有回落事件。
- 关闭代理后 goroutine 与连接计数归零。

NAT 实机验收（**本能力的核心门槛**）：

**NAT 打洞是本项目中唯一「单测通过也不算数」的能力。** 自动化测试只能证明状态机与协议正确性，无法证明在真实 NAT 设备组合下能否打通。实机验收必须执行并记录：

1. **环境组合**：至少覆盖「家庭宽带 + 家庭宽带」「家庭宽带 + 移动网络」「对称型 NAT + 锥形 NAT」「双栈环境下的 IPv4 与 IPv6」四类真实组合。
2. **执行方式**：使用固定基线 `e1f1d6ab1b591ec9b596f4b1b6a81cd2960c6314` 对应的官方 frpc 与 JRP jrps 在真实网络下运行 XTCP 代理，访客从另一网络发起访问。
3. **记录项**：环境描述（运营商、NAT 类型观测结果、地址族）、成功与否、失败时的结果类别、耗时、回落是否生效。
4. **证据留存**：结果与日志片段保存到忽略的临时目录，不入库；入库的是被证据钉住后写入规格与测试向量的行为事实。
5. **需用户确认实机通过**：以上结果必须由用户在真实网络环境确认。测试全绿不能替代实机验收，任何一项未通过则该能力不得标记为已交付。

## 6. 风险与待定

- **NAT 打洞成功率无法保证**：打洞成功率取决于两端 NAT 设备行为，某些组合（尤其双对称型）在技术上无法打通。P1 必须明确回落行为并让管理员可预期，而不是声称「总能打通」。
- **实机验收是硬依赖**：本能力没有真实网络验收就不能标记为交付，需要用户投入时间执行 §5 的组合验收。
- **策略分类的自判定可能误判**：JRP 的分类基于可观测行为，某些边界设备可能给出不稳定判定。缓解方式是参数可配置且失败类别可观测，而非追求一次判定准确。
- **IPv6 环境的行为可能与 IPv4 差异显著**：双栈环境下的候选构造顺序与可达性需要在实机中确认，本规格不预设优先级结论。
- **回落策略的产品口径待定**：「失败即拒绝」与「回落到服务端转发」哪个作为默认值，需要在 Web 配置界面定稿时确认；本规格只要求两者都可实现且可观测。
- **SUDP 留到 P2**：本轮明确不实现，避免把 UDP 变体的语义混入 STCP 的状态机。
- **依赖传输完成度**：完整矩阵验收依赖 FR-05b 与 FR-05c 的依赖获批；直连阶段使用 UDP 承载，不受该依赖影响。
