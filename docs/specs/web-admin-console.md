# 功能规格：Web 管理台

> 状态：草拟 · 关联 PRD：FR-11 · 分支：feature/web-admin-console

## 1. 背景与目标

管理员需要一个图形界面完成日常运维：管理客户端与代理、查看与应用配置版本、管理采集策略、管理通知目标、查看运行状态。若没有统一入口，这些动作都要靠手工调用 API 或直接改数据库，既不可控也不可审计。

本规格定义单管理员 React Web 管理台的技术形态、功能范围与嵌入方式。它只调用 `jrps` 的 `/api/v1` 管理 API，不直连 SQLite；生产构建产物只嵌入 `jrps`，不进入 Core、也不进入 `jrpc`。

使用者是唯一的管理员。属于 P1 阶段。前端技术选型与嵌入决策见 ADR-0006，控制面边界见 ADR-0003，认证与 CSRF 行为见 FR-02 规格，本规格不重复其正文。

## 2. 需求

- 技术栈固定为 React、TypeScript、Vite、Ant Design、TanStack Router、TanStack Query 与 MSW，以 pnpm workspace 组织；`apps/web` 是应用，`packages/*` 只被它单向消费。
- Web 只通过 `jrps` 管理 API 操作状态，不直连 SQLite，不绕过授权与审计。
- 生产构建产物只嵌入 `jrps`，随 `jrps` 二进制一起发布；不进入 Core，不进入 `jrpc`，`jrpc` 不提供 Web。
- 功能范围严格对应 PRD 已定的能力：客户端管理、代理管理、配置版本管理、采集管理、通知管理、状态查看。
- **不创建无法工作的空页面**：任何菜单项与路由都必须对应已交付且可操作的能力；未交付能力的页面、占位路由与功能开关一律不建。
- 登录与会话依赖 FR-02；所有修改请求必须携带并校验 CSRF token，会话失效时引导重新登录而不是静默重试。
- token 与通知秘密只在创建或轮换成功时展示一次，列表与详情只显示掩码。
- 界面文案使用简体中文；不声称凭证或正文已静态加密。
- 配置应用是异步流程：界面提交后展示受理状态，最终结果通过资源状态与 SSE 事件观察，不得假同步。
- 只读查看类操作不得产生副作用；正文查看等敏感读取由后端审计，前端不得缓存正文到持久化存储。

- 范围内：
  - 登录、会话失效处理与登出。
  - 客户端列表与详情、创建、发行 enrollment 凭据、token 轮换与吊销。
  - 代理列表与详情、创建、修改、删除，以及变更产生的配置版本。
  - 配置版本列表、desired/active/last-good 展示、触发应用、restore 历史版本。
  - 采集开关与保留策略管理、请求元数据查询与正文查看入口。
  - 通知目标管理、测试通知、发送结果查看。
  - 状态查看：服务、客户端、代理、连接、配置应用结果与容量摘要。
  - 开发期 MSW 模拟与前端自动化测试。
- 范围外：
  - **配置文件作为配置真源**：已被 ADR-0004 拒绝；Web 不提供配置文件导入导出、批量模板操作或以文件覆盖数据库的入口。
  - 新增 CLI 管理命令：Web 不替代也不新增命令行管理能力。
  - 多管理员、租户、角色与权限管理界面（P3）。
  - OIDC 与外部身份登录界面（P3）。
  - 独立部署的 Web 服务与服务端模板页面（ADR-0006 已拒绝）。
  - 数据节点管理、集群视图与分布式拓扑（P3）。
  - P2/P3 能力的占位页面、空路由、禁用开关与"敬请期待"页面。
  - jrpc 侧的任何 Web 界面或本地管理端口。

## 3. 设计

### 3.1 工程结构

沿用仓库现有 pnpm workspace：`apps/web` 为应用，`packages/ui`、`packages/devmock`、`packages/tsconfig`、`packages/eslint-config` 只被应用消费，不得反向依赖应用。

- 路由由 TanStack Router 管理，采用文件化或显式路由表，路由项与实际能力一一对应。
- 服务端状态与缓存由 TanStack Query 管理；列表使用游标分页参数，修改使用 `If-Match` 或显式 revision，冲突（409）时引导重新读取而不是静默覆盖。
- MSW 只在开发与测试启用，为前端测试提供 API 模拟；生产不得包含模拟逻辑。
- 类型检查、lint 与测试是构建前置条件；生产构建产物输出到应用构建目录，由 `jrps` 内嵌。

### 3.2 嵌入与发布

- `jrps` 以构建标签区分内嵌资源：带 Web 标签时使用生产构建产物，否则使用回退页面。两种形态都不改变 API 契约。
- Web 与 `jrps` 作为同一产品版本发布，避免静态资源与 API 契约错配；版本由根 `VERSION` 注入。
- 根任务编排顺序为：先构建 Web，再构建带内嵌资源的 `jrps`；不带前端的构建路径用于纯 Go 场景，不代表生产形态。

### 3.3 页面与能力映射

| 页面 | 对应能力 | 说明 |
|---|---|---|
| 登录 | FR-02 | 会话建立；未初始化时提示在本机执行初始化 |
| 客户端 | FR-07 | 列表、创建、enrollment 凭据发行、token 轮换与吊销、掩码展示 |
| 代理 | FR-06a/06b、FR-09 | 列表、创建、修改、删除；变更生成新配置版本 |
| 配置版本 | FR-10 | desired/active/last-good 展示、触发应用、restore、应用结果与阶段展示 |
| 采集 | FR-13 | 策略开关、30 天与 5 GiB 保留策略、元数据查询与正文查看入口 |
| 通知 | FR-15 | Webhook 与邮件目标管理、测试通知、发送结果 |
| 状态 | FR-14 | 服务、客户端、代理、连接、容量与配置应用摘要 |

每个页面都必须有真实可操作的数据来源；若某项后端能力尚未交付，对应页面不得先建。

### 3.4 认证、CSRF 与错误处理

- 登录成功后前端保存 CSRF 协议所需状态，并在所有修改请求中携带。
- 401 时清除本地状态并跳转登录；403（CSRF 失败）时提示并重新获取会话状态，不重试同一请求以免重复副作用。
- 409 时刷新资源并提示用户基于最新版本重试；422 时展示字段级校验信息。
- 错误展示使用后端问题详情中的中文 `title` 与 `detail`，前端不得自行拼接内部实现信息。

### 3.5 实时与异步

- 配置应用、通知结果与状态变化通过 `GET /api/v1/events` 的 SSE 观察；前端支持 `Last-Event-ID` 恢复，断线后重新订阅并刷新一次资源状态。
- SSE 只用于观察，前端不得通过 SSE 发送配置命令。
- 采集正文查看按需加载，不做整页缓存与本地持久化。

### 3.6 安全约束

- 前端不得把 token、密码、Cookie 或完整正文写入 `localStorage`、`sessionStorage`、URL 查询串或日志输出。
- 一次性 token 展示弹窗关闭后不再保留完整值。
- 所有用户输入在提交前做基本长度与格式校验，服务端仍为最终校验者。
- 页面输出按上下文转义，不直接渲染不可信 HTML。

## 5. 验收标准

- 自动化：类型检查、lint 与 Web 测试全部通过；生产构建成功产出构建目录。
- 自动化：受保护路由在未登录时跳转登录；登录成功后可访问，登出后回到登录。
- 自动化：修改类请求携带 CSRF 状态；缺失或无效时收到 403 且不产生副作用，页面给出中文提示。
- 自动化：409 revision 冲突时前端重新读取最新版本并提示重试，不发生静默覆盖。
- 自动化：token 创建或轮换后只在一次性弹窗展示完整值，列表与详情只显示掩码；页面 DOM 与前端存储中不含完整 token。
- 自动化：配置版本页面展示 desired、active、last-good 三个不同取值；触发应用后展示受理状态并通过 SSE 收敛到终态，不假同步。
- 自动化：restore 产生新 revision 而非修改历史版本，页面展示新版本条目。
- 自动化：采集策略页面可开关并修改 30 天与 5 GiB 保留策略；正文查看入口触发后端审计。
- 自动化：通知目标秘密只展示掩码，测试通知可发起并展示结果。
- 自动化：SSE 断线后重订阅并刷新一次资源状态；前端不通过 SSE 发送命令。
- 自动化：构建产物检查确认 `jrpc` 与 Core 的构建输入与依赖中不含前端资源或前端依赖。
- 边界：空列表、超长输入、服务端 500/503、分页末页、并发修改同一资源均有确定展示与中文提示。
- 实机（需用户确认，依赖 FR-02 提供 `jrps init` 与登录、FR-07 提供客户端与 token 管理先交付）：在本机以带 Web 标签构建并启动 `jrps`，用浏览器通过 HTTPS 打开管理台完成登录；依次执行创建客户端、发行 enrollment 凭据、创建代理、应用配置、查看状态、开启采集并查看一条元数据、配置一个通知目标并发送测试通知、吊销客户端 token；确认每个页面均可操作且无空白占位页，浏览器开发者工具中确认 Cookie 属性与 CSRF 请求头正确。

## 6. 风险与待定

- **风险**：前端页面先于后端能力交付会产生空页面。缓解方式是路由与菜单只注册已交付能力，交付后由后端验收驱动页面启用。
- **风险**：SSE 在代理或网关后可能被缓冲，导致状态不刷新。缓解方式是断线重订阅时主动刷新资源状态作为兜底。
- **风险**：一次性 token 展示若被截图或留存会造成泄漏，需在 UI 明确提示只显示一次。
- **风险**：Web 构建产物与 API 契约版本错配。缓解方式是二者同版本发布且构建顺序固定。
- **待定**：状态页面的指标字段集合需与 FR-14 的指标定义对齐后写入本文档。
- **待定**：采集正文在页面上的展示上限与截断策略需与 FR-13 的实现结果共同定稿。
