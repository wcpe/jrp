# 功能规格：请求与运行日志

> 状态：开发中 · 关联 PRD：FR-12 · 分支：feature/request-and-runtime-logging

## 1. 背景与目标

管理员在排障时需要两类信息：某一时刻系统内部发生了什么（运行日志），以及某个客户端或代理上跑过哪些请求（请求日志）。这两类信息的生产者、生命周期和访问敏感度都不同，混在一起会导致排障噪音大、敏感内容容易外泄、也无法针对请求量做单独降级。

FR-12 解决三件事：

1. 把运行日志与请求日志分成两条独立通道，各自有独立的等级、字段和降级策略。
2. 在全链路强制脱敏：token、密码、Cookie、Authorization 与请求正文原文不得出现在任何日志输出。
3. 让日志只能经管理员会话查看，并对查看动作本身留下审计记录。

使用者是管理员（经 Web 的日志查询与 `GET /api/v1/logs`）和运维排障流程。属于 P1 阶段，是 FR-13 正文采集、FR-14 监控、FR-15 通知与 FR-16 审计的诊断基础。存储与真源裁定见 ADR-0004，控制面与数据面边界见 ADR-0003，Core 公共 API 布局见 ADR-0012，本规格不重复其正文。

本功能只负责诊断输出，**不负责不可否认的操作记录**：后者是 FR-16 的审计事件，两者关系见 §3.6。

## 2. 需求

- 日志等级固定为 ERROR、WARN、INFO、DEBUG 四级；每条日志只使用一个等级，不得把同一事件以不同等级重复输出，也不得以 WARN 表达 ERROR 语义。
- 日志信息使用简体中文；字段值中的技术标识（问题码、阶段名、事件类型、代理名）保留原文以便检索。
- 运行日志覆盖：进程启停、配置应用阶段（prepare、health-check、atomic publish、drain）、客户端连接与断开、代理状态变化、传输与协议错误、通知发送结果、采集清理与容量事件、SQLite 写入异常、资源释放异常。
- 请求日志覆盖：代理维度的一次请求的方法、主机、路径摘要、状态码、请求与响应大小、耗时、结果类别。**请求正文原文不属于日志，属于 FR-13 的正文采集能力。**
- 请求元数据在采集关闭时不产生日志行；采集开启时按 FR-13 的有界队列进入持久化，不得在请求热路径同步写日志。
- 每条日志携带可关联上下文：时间、等级、组件名、request ID（管理请求）或客户端标识与代理名（数据面事件）。不得携带可反推凭证的字段。
- 日志输出目标由外壳决定；Core 侧只接受可选 `slog.Logger` 注入，未注入时不向标准输出直写。日志落盘、轮转和保留由外壳负责，Core 不做文件 IO 决策。
- 日志查看必须经管理员会话；只读查询也要求会话，且查询动作本身按 §3.5 的边界进入审计。
- 脱敏在写入点完成，而不是在读取时过滤：任何组件在调用日志接口前必须完成脱敏，日志通道不接受"原始值 + 事后过滤"的用法。
- 日志不得阻塞数据面：日志写入失败或缓冲满时按等级降级并计数，不得让转发路径等待。

- 范围内：
  - 中文分级日志的等级定义、字段模型与组件命名。
  - 运行日志与请求日志两条通道的划分、生产点与降级策略。
  - 脱敏矩阵与在写入点强制脱敏的约束。
  - Core 侧可选 logger 注入与"未注入不直写"的约定。
  - 外壳侧日志落盘、轮转、保留与按条件过滤查询。
  - `GET /api/v1/logs` 的会话保护、过滤参数与脱敏输出。
  - 日志查看动作的审计边界。
- 范围外：
  - **配置文件作为配置真源**：已被 ADR-0004 拒绝；日志等级、输出目标和保留参数只存 SQLite 并经管理 API 变更，不支持日志配置文件。
  - HTTP 正文原文进入日志：正文归 FR-13，本功能不记录请求或响应正文。
  - 结构化指标聚合、告警判定与阈值：属 FR-14。
  - 审计事件的模型与查询：属 FR-16。
  - 通知发送与重试：属 FR-15。
  - 日志落盘文件的静态加密：项目不提供，不得声称。
  - 集中式日志后端、分布式追踪、日志采集代理与远程日志推送（P3）。
  - 多管理员可见性分级、按租户隔离日志与 RBAC 化日志权限（P3）。
  - 日志全文检索引擎与外部分词服务。

## 3. 设计

### 3.1 模块与依赖方向

- Core 侧：只定义可选日志注入点与脱敏后的事件字段。Core 不知道日志文件、轮转或保留策略，也不导入任何日志库之外的外壳类型。可选 `*slog.Logger` 注入保持 ADR-0012 的公共面约束，注入与否不改变 Engine 行为契约。
- jrps 侧：持有日志配置、落盘器、轮转与保留、查询服务与管理端点。请求日志的生产点位于采集适配层（FR-13），但本功能定义其日志字段与脱敏规则。
- jrpc 侧：持有本地运行日志与本地配置应用日志，输出到自身数据目录；不向服务端上传日志。
- 依赖方向：外壳 → Core 单向。Core 事件（FR-27）经有界通道交给外壳的日志适配层，适配层负责落盘与查询，不得反向让 Core 读取日志配置。

### 3.2 两条日志通道

| 通道 | 生产者 | 关键字段 | 降级策略 | 持久化 |
|---|---|---|---|---|
| 运行日志 | 进程生命周期、配置应用编排、Core 事件适配、通知与清理任务 | 时间、等级、组件、事件名、中文摘要、request ID 或客户端/代理标识、错误摘要 | 缓冲满时丢弃 DEBUG 与 INFO，保留 WARN 与 ERROR | 外壳落盘，按大小与天数轮转 |
| 请求日志 | 采集适配层在采集开启时按请求生成 | 时间、代理标识、客户端标识、方法、主机、路径摘要、状态码、请求大小、响应大小、耗时毫秒、结果类别 | 队列满时整条丢弃并计入采集降级计数，不阻塞转发 | 元数据随 FR-13 批量写 SQLite；本功能只定义日志视图 |

两条通道的硬边界：

- 运行日志可以没有任何请求而存在；请求日志在采集关闭时完全为空。
- 请求日志不重复记录运行日志已覆盖的进程级事件。
- 请求日志不携带正文、不携带 Cookie 值、不携带 Authorization。

### 3.3 等级定义

| 等级 | 使用场景 | 示例 |
|---|---|---|
| ERROR | 功能失败且需要管理员介入，或资源处于不一致状态 | 配置应用 publish 失败、SQLite 迁移失败、正文分段写入失败 |
| WARN | 已降级但服务仍可用，或接近容量与限制边界 | 采集队列降级丢弃、通知重试中、正文容量接近上限 |
| INFO | 正常状态迁移与生命周期事件 | 客户端连接成功、配置应用阶段完成、清理任务执行结果 |
| DEBUG | 排障细节，生产默认关闭 | 事件通道水位、批处理刷写统计、单次请求耗时明细 |

同一事件只在一个等级输出一次。重试类事件按"首次失败记 ERROR 或 WARN、后续重试记 DEBUG、最终失败记 ERROR"的规则收敛，避免刷屏。

### 3.4 脱敏矩阵

| 数据类别 | 处理规则 |
|---|---|
| 客户端 token | 禁止出现完整值；只允许出现 token 摘要前缀与客户端标识 |
| 管理员密码与派生材料 | 完全禁止，包括长度、前缀与哈希片段 |
| Cookie 值 | 完全禁止；只允许出现 Cookie 名称与存在性标记 |
| Authorization 头 | 完全禁止；只允许出现方案类别（如 bearer、basic） |
| 请求与响应正文原文 | 完全禁止；正文只能经 FR-13 的分段文件访问，且访问动作审计 |
| 查询串与路径 | 只保留路径摘要；查询串中的键值视为敏感，按名称掩码 |
| 通知目标秘密（Webhook secret、邮箱密码） | 完全禁止；只允许出现目标标识与掩码 |
| 远端地址 | 只记录地址摘要层级，不记录可反推凭证的字段 |
| request ID、客户端标识、代理名、revision | 允许明文出现，用于关联检索 |

脱敏在写入点完成。实现方式上提供统一的脱敏辅助入口，供各生产点调用；测试以"日志输出中不含敏感串"为断言，而不是以"调用了脱敏函数"为断言。

### 3.5 访问控制与审计

- `GET /api/v1/logs` 需要有效管理员会话；未认证返回 401。
- 只读查询不要求 CSRF（只读 GET 不产生副作用，符合 `docs/API.md` §1.3），但响应体不得包含任何未脱敏字段。
- 查询支持时间范围、等级、组件、关联 ID 与游标分页；过滤参数需做长度与格式校验，非法参数返回 400 问题详情。
- 响应使用 UTF-8 JSON，时间使用 RFC 3339 UTC，大小用整数字节，耗时明确带毫秒后缀。
- 日志查询属于安全敏感读取：按 SECURITY §5 与 FR-16 的口径，查看日志须写入审计事件，审计只记录查询条件摘要与结果条数，**不记录被查日志的敏感内容**。
- 日志不提供批量导出接口；P1 只提供分页查询。

### 3.6 日志与审计的边界

| 维度 | 日志（本功能） | 审计（FR-16） |
|---|---|---|
| 目的 | 诊断与排障 | 不可否认的操作记录 |
| 触发 | 状态变化、错误、降级自动产生 | 安全敏感操作显式产生 |
| 完整性要求 | 允许按等级降级与丢弃 | 不允许因容量或性能丢弃 |
| 保留 | 由外壳轮转策略管理 | 独立于正文保留，随审计保留策略管理 |
| 内容 | 中文摘要、组件、关联 ID | 主体、动作、对象、结果、时间、脱敏上下文 |

同一操作可以同时产生日志与审计，但两者不得互相替代：审计成功不代表日志有输出，日志有输出也不构成审计证据。

### 3.7 Core 事件到日志的映射

- 外壳订阅 FR-27 的有界类型化事件通道，把事件映射为运行日志；映射过程不回读 Core 内部状态，只用事件自带的只读快照（FR-27 的 `State` 快照）重建缺失视图。
- 事件通道溢出时，日志侧收到重同步要求后执行一次快照重建并记录一条 WARN，不得因缺少事件而猜写日志。
- 映射不得阻塞：日志适配层是事件消费者，其消费速度不得反向影响数据面（ADR-0003）。

## 5. 验收标准

正常路径：

- 自动化：进程启动、客户端连接、配置应用四阶段、代理状态变化均产生 INFO 运行日志，信息为中文且等级唯一。
- 自动化：配置应用 publish 失败产生 ERROR 日志，内容含 revision、阶段与 request ID，不含凭证或正文。
- 自动化：采集开启且请求通过后产生请求日志行，字段包含方法、主机、路径摘要、状态码、大小与耗时毫秒。
- 自动化：已登录管理员可按时间、等级、组件与关联 ID 过滤查询，响应为脱敏 JSON 且支持游标分页。

边界：

- 自动化：采集关闭时在 HTTP 与 TCP 代理上持续转发流量，请求日志零输出，运行日志不受影响。
- 自动化：日志缓冲满时 DEBUG 与 INFO 被丢弃，WARN 与 ERROR 仍保留；丢弃计数在指标中可见。
- 自动化：超长路径、超长主机、非法过滤参数、空结果集与分页末页均有确定行为与中文提示。
- 自动化：Core 未注入 logger 时不向标准输出直写任何内容。
- 自动化：事件通道溢出后收到重同步要求时记录一条 WARN，并通过只读快照重建，不猜写日志。

错误路径：

- 自动化：任何日志输出中不含完整 token、密码、Cookie 值、Authorization 或正文原文；对这五类值逐一构造用例断言。
- 自动化：日志写入失败（如磁盘不可写）时不阻塞数据面，转发吞吐在既定容差内（容差数值由 FR-14 压测定稿后补齐，补齐前不作为门禁），并记录一条 ERROR。
- 自动化：未认证访问 `GET /api/v1/logs` 返回 401；会话失效后返回 401。
- 自动化：日志查询动作写入审计事件，审计内容只含查询条件摘要与结果条数。
- 自动化：同一事件不因重试而在多个等级重复输出；首次失败、后续重试与最终失败各只出现一次对应等级。

实机（需用户确认）：在 Windows 与 Linux 上各启动一次 jrps 与 jrpc，制造一次配置应用失败与一次通知失败，在 Web 的日志页按等级与关联 ID 过滤查看，确认中文信息可读、无敏感字段、无刷屏重复；同时在数据目录中确认日志文件权限仅限运行账户。

## 6. 风险与待定

- **风险**：请求日志在 200 客户端与 2000 代理的规模基线下可能产生大量行，放大 SQLite 写竞争。缓解方式是请求日志不单独落表、不阻塞转发、按队列降级，并在 FR-14 中观察写入延迟与降级计数。
- **风险**：脱敏依赖每个生产点自觉调用，容易在新增代码时漏掉。缓解方式是测试以输出内容断言，并把脱敏矩阵作为代码评审清单项。
- **风险**：日志落盘可能包含历史敏感数据而保留期长于正文。缓解方式是日志保留与正文保留分开管理，且备份介质权限不低于生产数据目录。
- **风险**：DEBUG 级在生产开启会显著增加 IO。缓解方式是生产默认关闭 DEBUG，仅在排障期由管理员显式开启并自动回落。
- **待定**：日志文件的轮转大小上限与保留天数默认值需在压测后在此规格中定稿，暂按有界与可配置下限实现。
- **待定**：日志是否需要在 Web 上提供按代理维度的快捷入口，取决于 FR-11 状态页与日志页的信息架构统一结果。
