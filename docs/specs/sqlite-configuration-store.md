# 功能规格：SQLite 配置存储

> 状态：草拟 · 关联 PRD：FR-09 · 分支：feature/sqlite-configuration-store

## 1. 背景与目标

JRP 的配置、revision 和必要运行元数据需要可审计、可断电恢复、可下发，但又不能因此给单机部署引入外部基础设施。`jrps` 需要在本地持久化管理员与各客户端期望的配置，`jrpc` 需要在本地持久化服务端下发的 desired state 与自身应用结果。

本规格解决两件事：

1. 用 SQLite 作为 `jrps` 与 `jrpc` **各自独立**的持久化真源，明确实体清单与 revision 语义。
2. 划清持久化状态与运行状态的边界：SQLite 中的 desired 不得冒充 Core 的 active，Core 的内存快照也不得反向成为持久化真源。

使用者是 `jrps`、`jrpc` 外壳中的管理适配层，以及依赖其提供 desired 快照的控制面流程。属于 P1 阶段，是 FR-10 无中断应用与 FR-08 配置下发的数据前提。技术选型与真源裁定见 ADR-0004，边界裁定见 ADR-0003，采集存储分离见 ADR-0007，本规格不重复其正文。

## 2. 需求

- `jrps` 与 `jrpc` 各自持有独立 SQLite 数据库文件，位于各自数据目录内；两者禁止共享数据库文件，也禁止跨进程直连对方数据库。
- 数据库文件、WAL 与 SHM 只由所属外壳进程读写；数据目录是信任边界。
- 实体覆盖 ARCHITECTURE §3.2 的清单：管理员与会话、客户端、代理、配置版本、通知目标与 outbox、请求元数据、正文分段索引、审计事件。
- 配置版本中的 desired、active、last-good 三个 revision 必须分开表达、分开写入、分开审计，不得用单一字段兼表多种含义。
- 每个配置版本的内容是不可变的：新版本以新记录追加，禁止原地修改已发布版本的内容。
- 进程重启后由外壳从 SQLite 恢复 desired，再经与常态相同的应用流程建立 active；重启期间不得把上一次的内存快照写回为真源。
- Core 数据热路径不得查询 SQLite；关闭正文采集时，数据转发路径不得进入 SQLite 请求记录写入路径。
- 管理写入与统计写入通过有界通道与批处理同数据面隔离，队列满时按事件等级降级，不得阻塞转发。
- 凭证与 HTTP 正文按已接受风险明文静态存储，文档、日志、UI 与审计不得声称已加密。
- 迁移在进程启动时以事务方式执行；迁移失败必须拒绝启动并在日志中给出中文原因，不得留下半迁移状态。
- 技术栈固定为 Gin、GORM 与纯 Go SQLite 驱动（CGO-free），以满足 Windows、Linux、macOS 交叉构建。这些依赖只出现在外壳，不进入 Core。

- 范围内：
  - jrps 与 jrpc 各自的 SQLite schema 与迁移。
  - 上述八类实体的持久化模型与索引。
  - desired、active、last-good revision 与 apply result 的表达与审计。
  - 重启后从 SQLite 恢复 desired 的流程约束。
  - 数据面隔离约束与批处理写入通道。
- **范围外**：
  - **配置文件作为配置真源**：该备选方案已由 ADR-0004 明确拒绝，本功能不提供配置文件读写、导入导出或以文件覆盖数据库的路径。
  - 配置文件解析器、目录监听与文件格式兼容层。
  - 新增 CLI 管理命令：初始化之外的管理能力只经管理 API 与 Web。
  - 共享数据库、网络数据库、PostgreSQL、Redis、消息队列与对象存储。
  - 数据表或字段层面的多租户、角色、节点预留。
  - **在线备份与恢复功能**：不在 PRD §4 的 FR 列表中，本功能不提供备份协调点、备份接口或恢复流程；备份属于独立的后续需求。
  - 备份介质加密、异地复制与自动化定时备份调度。
  - 采集正文的具体分段格式与容量清理实现（属 FR-13 与 ADR-0007）。

## 3. 设计

### 3.1 模块与依赖方向

持久化能力全部位于外壳内部：`jrps` 侧放在管理适配包中，`jrpc` 侧放在客户端适配包中。两侧各自维护自己的模型与迁移，互不导入、不共享 schema 文件。

- 外壳 → Core：单向。外壳把 SQLite 中的 desired 内容转换为 Core 配置构建器可接受的不可变快照（FR-32 的构建与校验入口），Core 不接触 GORM 模型。
- Core → 外壳：只通过不可变快照应用结果、运行事件与只读状态快照回流，事件经有界通道交给适配层写入 SQLite。
- 数据库模型、会话模型、通知模型与管理 DTO 是外壳私有类型，不得进入 Core。

### 3.2 数据库实例边界

`jrps` 数据库保存服务端全部控制面状态；`jrpc` 数据库只保存属于本客户端身份的 desired state、本地应用结果与本地运行元数据。两者默认数据目录分离，SQLite 路径是引导参数之一，变更需要重启。

启动流程：

1. 打开本进程独占的 SQLite 连接，设置 WAL 与忙等待超时。
2. 在事务中执行迁移到当前版本，失败则拒绝启动。
3. 读取初始化标记；未初始化时按 FR-02 的初始化流程处理，初始化之前管理 API 除健康检查外返回 503。
4. 读取最新 desired revision，进入与常态相同的配置应用流程建立 active。

### 3.3 实体清单

| 实体 | 关键字段要点 | 说明 |
|---|---|---|
| 管理员 | 凭据派生材料、初始化时间、初始化标记 | P1 只有一个管理员记录，不提供角色或租户字段 |
| 会话 | 会话标识摘要、创建时间、过期时间、失效状态、CSRF 状态 | 不保存可重放的服务端会话密钥明文 |
| 客户端 | 身份标识、名称、独立 token 摘要、enrollment 状态、连接状态、desired/active revision 引用 | token 只存摘要，明文只在创建响应中返回一次 |
| 代理 | 所属客户端、类型、入口与端口、目标地址、传输与安全参数、采集开关 | 变更生成新的配置版本 |
| 配置版本 | 版本号、不可变内容、创建者、创建时间、应用状态、last-good 关系、与前一版本的差异摘要 | 内容不可变，追加写入 |
| 通知目标与 outbox | 目标类型、脱敏后的目标摘要、秘密材料、待发送事件、重试状态与退避 | 秘密只在写入时接收，读取时掩码；发送在事务提交后触发 |
| 请求元数据 | 所属代理、时间、方法、主机、路径摘要、状态、大小、耗时、正文段引用 | 仅在采集开启时产生 |
| 正文分段索引 | 段标识、偏移或条目、压缩后大小、保留截止时间、删除状态 | 正文不存入 SQLite 大字段，见 ADR-0007 |
| 审计事件 | 时间、主体、动作、对象、结果、脱敏上下文 | 不记录完整秘密或完整正文 |

### 3.4 revision 语义与审计

三个 revision 分列表达，各自有独立写入点与审计动作：

- **desired revision**：SQLite 中管理员或服务端期望应用的版本，是持久状态。创建代理、修改代理、删除代理、restore 与 jrpc 接收下发都会产生新的 desired 版本。
- **active revision**：Core 当前对新连接生效的不可变快照版本，是运行状态。它只能在 publish 成功后由外壳记录到 SQLite，用于展示与重启比对，不构成真源。
- **last-good revision**：最近一次成功完成 prepare、health-check、publish 的版本。它只在 publish 成功后推进，用于失败保留与回滚起点。按 ADR-0012，运行态 last-good 由 Core 持有，SQLite 保存的是 Apply 结果记录，用于审计与重启后展示。

硬边界：

- SQLite 的 desired 不得被当作 Core 的 active 使用；未成功 publish 的 desired 版本对数据面没有任何效力。
- Core 的内存快照不得反向写回成为持久化真源；SQLite 只接受来自审计过的状态迁移。
- **真源性质只属于 desired**：Core 运行态的 active 与 last-good 服务于运行时决策，SQLite 中的对应记录服务于审计与展示，二者目的不同，不构成双真源（ADR-0012）。
- 三个 revision 的每次变化都必须产生审计事件与（配置类变化）apply result 记录，应用状态迁移见 FR-10 规格。
- 进程重启后 active 初始为空，由外壳以 desired 为输入重新走完整应用流程；不得跳过 health-check 直接声明 active。

### 3.5 数据面隔离

- Core 热路径不持有数据库句柄，也不查询 SQLite。
- 采集关闭时，请求记录写入路径完全不启用，数据转发不产生元数据行。
- 采集开启时，元数据经有界队列批量写入，队列满时丢弃低等级统计并在指标中反映，不得阻塞转发。
- 通知使用事务 outbox：业务事务提交成功后才由发送器读取 outbox 执行外部副作用，禁止事务内远程调用。

### 3.6 安全与一致性

- 所有数据库访问使用 ORM 参数绑定，不拼接不可信 SQL。
- 凭证按已接受风险明文静态存储，但 API、日志、UI、审计一律脱敏；token 只存摘要。
- 版本迁移必须向后兼容已落库数据；破坏性迁移需要独立规格与升级说明，不在本规格内定义。

## 4. 任务拆分

- [ ] 先写失败测试：jrps 与 jrpc 打开同一数据库文件应失败；desired 与 active 混用场景应失败；采集关闭时数据面产生请求元数据行的用例应失败。
- [ ] 定义 jrps 与 jrpc 各自的 GORM 模型与初始迁移，迁移在事务中执行，失败拒绝启动。
- [ ] 实现配置版本表与 desired、active、last-good 三个 revision 的独立读写点与审计写入。
- [ ] 实现不可变版本约束：版本记录只允许追加，修改历史版本内容必须被拒绝。
- [ ] 实现重启恢复流程：启动时从 SQLite 读取 desired 并进入标准应用流程，不直接声称 active。
- [ ] 实现有界批处理写入通道与降级策略，并验证队列满时不阻塞数据面。
- [ ] 实现 outbox 读写与事务提交后触发边界，禁止事务内远程调用。
- [ ] 补齐 token 摘要存储、秘密读取掩码与审计脱敏测试。
- [ ] 运行 jrps、jrpc 测试、静态检查与构建；同步 PRD、ARCHITECTURE、API、OPERATIONS、SECURITY、CHANGELOG 中受影响内容。

## 5. 验收标准

- 自动化：jrps 指向 jrpc 的 SQLite 文件或两者指向同一路径时启动失败并给出中文明确错误；不存在共享数据库的代码路径。
- 自动化：创建或修改代理后生成新的配置版本记录，历史版本内容保持不变；尝试更新已有版本内容被拒绝。
- 自动化：三个 revision 在 prepare、publish、drain 各阶段的取值变化与审计事件一一对应；publish 未成功时 last-good 不推进。
- 自动化：进程重启后 active 初始为空，desired 从 SQLite 恢复并重新走完整应用流程；不存在把内存快照写回为 desired 的路径。
- 自动化：采集关闭时在 TCP 或 HTTP 代理上持续转发流量，请求元数据表与正文分段索引均无新增行；转发吞吐不受数据库写入路径影响。
- 自动化：采集开启时元数据批量写入，批处理队列满时统计降级且转发不阻塞。
- 自动化：token 只以摘要落库；读取接口、日志与审计事件中不含完整 token。
- 自动化：迁移中断后重启能从同一事务边界恢复到一致状态，不出现半迁移可启动状态；迁移失败时启动被拒绝。
- 自动化：outbox 中的通知在业务事务回滚后不存在可发送记录。
- 边界：空数据库首次启动、超大数据目录路径、并发启动同实例、磁盘写满时的写入失败降级均有明确行为与中文日志。
- 实机（需用户确认）：在 Windows、Linux、macOS 三平台上以低权限账户启动 jrps 与 jrpc，确认各自数据目录内生成独立 SQLite 与 WAL，权限仅限运行账户。

## 6. 风险与待定

- **风险**：SQLite 写竞争可能在采集高开启率与多代理并发统计下放大。缓解方式是批处理、有界队列与降级策略，并在 FR-14 指标中观察写入延迟。
- **风险**：迁移脚本跨版本演进可能与回滚后的旧二进制不兼容。缓解方式是只做向后兼容迁移，破坏性变更独立成规格并配套升级说明。
- **风险**：明文凭证与正文落盘的风险已接受，但要求文档与 UI 不得声称加密；交付前需复核文案。
- **待定**：批处理队列容量与刷写间隔的具体数值需在 FR-14 压测后在此规格中定稿，暂按有界与可配置下限实现。
- **待定**：运维手册描述的手工备份步骤（停写后复制 SQLite、WAL 与 SHM）是否需要固化为工具能力，取决于后续独立备份需求的立项结果；本功能只保证落库格式可被标准 SQLite 工具读取。
