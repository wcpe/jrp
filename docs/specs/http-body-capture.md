# 功能规格：HTTP 正文采集

> 状态：草拟 · 关联 PRD：FR-13 · 分支：feature/http-body-capture

## 1. 背景与目标

排障时管理员常常需要看到某个 HTTP 请求到底发了什么。但正文体积大、内容敏感，若默认全采或把正文塞进数据库，会同时放大隐私风险、磁盘占用和 SQLite 写竞争。

FR-13 解决四件事：

1. 把采集做成**默认关闭、逐代理开启**的能力，让最小采集原则成为默认状态。
2. 只采集 JRP 真正看得见的明文 HTTP；未由 JRP 终止 TLS 的 HTTPS 透传不解析正文，不做虚假承诺。
3. 把元数据与正文分开存：元数据批量写 SQLite，正文流式压缩写入分段文件，避免整段加载进内存。
4. 用 30 天与 5 GiB 双重保留上限约束增长，任一先到即清理，且清理过程维护索引与文件的一致性。

使用者是管理员（经 Web 采集页与 `/api/v1/captures`）与排障流程。属于 P1 阶段。存储分离决策见 ADR-0007，配置真源见 ADR-0004，数据面隔离见 ADR-0003，事件通道见 FR-27，本规格不重复其正文。

## 2. 需求

- 采集默认关闭；只有管理员在指定代理上显式开启后才对该代理生效。不得提供全局一键全量采集作为默认或快捷路径。
- 采集开关是代理配置的一部分，随配置版本进入不可变快照；变更走 prepare、health-check、atomic publish、drain（FR-10），不得以重启生效。
- P1 只采集明文 HTTP。对未由 JRP 终止 TLS 的 HTTPS 透传，JRP 不掌握明文，不解析、不落盘、不产生正文记录。
- 请求元数据包含：所属代理、时间、方法、主机、路径摘要、状态码、请求大小、响应大小、耗时、结果类别、正文段引用。
- 元数据批量写入 SQLite，经有界队列异步落库；队列满时按等级降级并计入指标，不得阻塞代理转发。
- 正文不进 SQLite 大字段，也不在内存中整段缓冲：正文以流式压缩写入分段文件，按大小滚动生成新段。
- 正文采集设置内存、单请求正文、并发、磁盘与超时上限；超限按截断或放弃记录处理，并留下可观测计数。
- 默认保留 30 天，正文总量上限 5 GiB；**任一条件先到即触发清理**。清理必须同时维护 SQLite 索引与分段文件的一致性。
- 保留策略（默认关闭、30 天、5 GiB）可经 `GET/PUT /api/v1/capture-policy` 管理，变更须审计。该端点的契约与策略值归属见 FR-16 规格，「本规格只负责按策略执行清理」。
- 关闭采集时，数据转发路径不得访问 SQLite 请求记录；这不是"写空数据"，而是请求记录路径完全不启用。
- 正文查看、导出与删除必须审计；API 不得暴露真实分段文件路径。
- 未采集、已清理或不可见的正文返回 404 或 410 的稳定问题码，不返回空内容冒充命中。
- 凭证与正文按已接受风险明文静态存储，文档、UI 与 API 不得声称已加密；只能表述为脱敏、访问控制与审计。

- 范围内：
  - 代理级采集开关及其随配置版本生效的路径。
  - 明文 HTTP 请求元数据的字段模型、有界队列与批量落库。
  - 正文流式压缩写入分段文件的写入路径、滚动策略与上限。
  - 30 天与 5 GiB 双重保留、清理任务与索引文件一致性维护。
  - `/api/v1/captures` 的元数据查询、正文读取、删除与策略管理。
  - 正文查看、导出、删除的审计写入。
  - "关闭采集时数据面不进入 SQLite 请求记录路径"的可验证设计。
- 范围外：
  - **配置文件作为配置真源**：已被 ADR-0004 拒绝；采集开关与保留策略只存 SQLite 并经管理 API 变更。
  - **HTTPS 终止后的正文采集**：P1 不终止 TLS；JRP 终止 TLS 后的采集属 P2（FR-21），本功能不预留开关、字段或页面。
  - 深度流量与请求分析、按内容检索、请求重放（P2）。
  - 对象存储、远程归档与跨节点正文汇聚（P3）。
  - 正文与凭证的静态加密：项目不提供，不得声称。
  - 正文批量导出为归档包以外的分发形态、定时导出任务与订阅推送。
  - 对非 HTTP 代理（TCP、UDP、STCP、XTCP）的载荷采集。

## 3. 设计

### 3.1 模块与依赖方向

- Core 侧：在代理数据路径上提供**请求观察点**，只输出不含正文原文的元数据事件与可选的正文流读取接口。Core 不落盘、不压缩、不查 SQLite、不知道分段文件的存在。
- jrps 侧：持有采集适配层，负责按代理开关决定是否挂载观察点、消费元数据事件、批量写 SQLite、流式压缩写分段文件、执行清理任务与提供管理端点。
- 依赖方向：外壳 → Core 单向。观察点的数据经 FR-27 的有界事件通道或外壳注入的只读流接口交给适配层；Core 不回调外壳的持久化逻辑。
- 采集开关随不可变配置快照下发；Core 依据快照中该代理是否开启决定是否产出观察数据，不做全局开关判断。

### 3.2 采集开关与生效路径

```text
管理员在代理上开启采集
   │
   ▼
生成新的 desired revision（FR-09）
   │
   ▼
prepare / health-check / atomic publish / drain（FR-10）
   │
   ▼
新快照中该代理的采集开关生效：观察点挂载，元数据开始产出
   │
   ▼
关闭采集：新快照中开关关闭，观察点卸载，请求记录路径不再启用
```

- 开关状态是快照的一部分，不存在"运行时临时开关"绕过配置版本。
- 关闭后已有正文仍受保留策略约束，直到清理触发或管理员显式删除；关闭不等于立即擦除，界面须如实表述。
- 观察点的挂载与卸载随 publish 一次性切换，不存在半挂载状态。

### 3.3 明文边界

| 场景 | 是否采集正文 | 说明 |
|---|---|---|
| 明文 HTTP 代理且开关开启 | 采集 | JRP 可见明文，写入压缩分段文件 |
| 明文 HTTP 代理且开关关闭 | 不采集 | 不产生元数据，不触发请求记录路径 |
| HTTPS 透传（JRP 未终止 TLS） | 不采集 | JRP 不掌握明文；不解析、不落盘、不产生正文记录 |
| 非 HTTP 代理类型 | 不采集 | 范围外 |

HTTPS 透传代理即使被误开采集开关，也只可能不产生正文记录；实现上在开关校验阶段即拒绝为 HTTPS 透传代理开启正文采集，并返回明确中文提示，避免管理员获得虚假预期。

### 3.4 元数据与正文分离存储

**元数据（SQLite）**：

| 字段要点 | 说明 |
|---|---|
| 所属代理、客户端标识、时间 | 用于过滤与关联 |
| 方法、主机、路径摘要 | 路径只保留摘要，查询串按键名掩码 |
| 状态码、请求大小、响应大小、耗时毫秒 | 数值字段，用于统计 |
| 结果类别 | 成功、超时、中断、超限截断等 |
| 正文段引用 | 段标识与偏移或条目，可为空 |

元数据经有界队列批量写入：按条数或时间间隔成批提交，单批有上限；队列满时丢弃常规级统计并累计计数，写入延迟与丢弃计数进入 FR-14 指标。

**正文（压缩分段文件）**：

- 正文以流式方式压缩写入当前活跃分段文件，全程不把整段正文加载进内存。
- 分段文件按大小滚动：达到段大小上限后新建分段；索引记录段标识、偏移或条目、压缩后大小、原始大小、保留截止时间与删除状态。
- 单请求正文超过上限时截断并记录截断标记；元数据如实标记"已截断"，不伪造完整内容。
- 写入受磁盘剩余空间、并发写入数与超时上限约束；超限放弃本次正文并保留元数据行（正文段引用为空）。
- 分段文件位于数据目录内，权限仅限运行账户；API 不返回真实文件路径。

### 3.5 保留与清理

- 两个限制独立计算：**时间上限默认 30 天**，**总量上限默认 5 GiB**，任一先到即触发清理。
- 清理按分段粒度执行：优先回收保留截止时间最早的整段，避免随机删除破坏索引连续性。
- 清理顺序固定为：标记段为删除中 → 删除分段文件 → 在同一事务中删除或标记对应索引与元数据引用 → 提交。任一步失败必须可重入重试，不得留下孤儿段或悬空引用。
- 提供一致性检查：启动时与清理后比对索引与文件清单。孤儿段（有文件无索引）按可审计方式回收；缺失文件（有索引无文件）标记不可见并在查询时返回 410，**不伪造正文**。
- 清理任务与数据面隔离：清理在后台执行，有并发与 IO 限制，不得阻塞转发。
- 容量接近上限时产生 WARN 日志与监控指标，达到上限触发清理，不做静默丢弃。

### 3.6 关闭采集时不触发 SQLite 请求记录路径

这是架构红线（ADR-0007 后果、`.claude/rules/architecture-invariants.md` §5），设计上以"路径不启用"而非"写空"来满足：

- 采集关闭时代理快照不挂载观察点，请求转发路径上不存在任何元数据生产代码的执行分支。
- 请求记录的队列、批处理与落库协程在采集关闭时不启动，不持有数据库写入句柄执行请求记录写入。
- 可验证设计：测试在请求记录写入路径上放置计数探针（对请求元数据表的写入与查询均计数），采集关闭时跑持续流量，断言计数恒为零；同时用一份"SQLite 请求记录路径不可用"的注入（例如让请求记录写入器直接返回错误）跑流量，断言转发完全不受影响，以此证明路径未启用而非恰好没写。
- 采集开启时同一探针计数大于零，证明探针本身有效，避免"探针坏了导致恒零"的假阳性。

### 3.7 管理接口与安全边界

- `GET /api/v1/captures`：分页查询元数据，不默认携带正文。
- `GET /api/v1/captures/{captureId}`：查询单条元数据。
- `GET /api/v1/captures/{captureId}/body`：流式读取正文，写入审计。
- `DELETE /api/v1/captures/{captureId}`：删除索引与正文引用，写入审计。
- `GET/PUT /api/v1/capture-policy`：策略端点的契约与策略值管理归属 FR-16 规格，本规格只按该策略执行清理与容量控制。
- 所有端点需要管理员会话；修改类端点还须校验 CSRF。
- 正文字段在元数据响应中不出现；正文只经专门端点按需流式返回，且返回时不做缓存。
- 问题详情不暴露文件路径、SQL 或内部地址。

## 5. 验收标准

正常路径：

- 自动化：在明文 HTTP 代理上开启采集并应用后发起请求，产生一条元数据行与一条正文段引用；正文可经专门端点流式读回且内容一致。
- 自动化：元数据字段包含方法、主机、路径摘要、状态码、请求与响应大小、耗时毫秒；路径摘要不含查询串敏感键值。
- 自动化：关闭采集并应用后再发起请求，不产生新的元数据行与正文段。
- 自动化：策略端点可读写默认关闭、30 天与 5 GiB 三个值，变更写入审计。

边界：

- 自动化：**采集关闭时请求记录写入计数探针恒为零**；同时以"请求记录写入器不可用"注入跑流量，转发吞吐与错误率在既定容差内（容差数值由 FR-14 压测定稿后补齐，补齐前不作为门禁）无变化。
- 自动化：采集开启时同一探针计数大于零，证明探针有效。
- 自动化：单请求正文超过上限时被截断，元数据标记已截断；不产生内存峰值异常。
- 自动化：分段达到大小上限后滚动新建分段，索引中的段标识与偏移正确。
- 自动化：保留时间设为极小值与总量设为极小值时，两个限制各自独立触发清理，先到者生效。
- 自动化：并发写入正文时受并发与超时上限约束，超限条目被放弃记录且元数据标记正文缺失。
- 自动化：清理后索引与文件清单一致；人为制造孤儿段与缺失文件后，一致性检查分别按回收与标记不可见处理，且处理动作可审计。

错误路径：

- 自动化：为 HTTPS 透传代理开启正文采集被拒绝并返回明确中文提示，且不产生正文记录。
- 自动化：HTTPS 透传流量经过不产生任何元数据行或正文段。
- 自动化：未认证访问采集端点返回 401；修改类请求缺少或错误 CSRF 返回 403 且无副作用。
- 自动化：未采集、已清理或不可见的正文返回 404 或 410 稳定问题码，问题详情不含文件路径。
- 自动化：正文查看、导出与删除各写入一条审计事件，审计不含完整正文。
- 自动化：SQLite 不可用或磁盘写满时，采集降级不阻塞转发，并记录 ERROR 与降级计数。
- 自动化：正文字段不出现在任何元数据响应中；SQLite 中不存在存储正文的大字段列。
- 自动化：在 `-race` 下执行上述用例无竞态报告。

实机（需用户确认）：在一台机器上启动 jrps 与一个 jrpc，建立一个明文 HTTP 代理并开启采集，用浏览器或命令行发起含查询串与表单正文的请求，在 Web 采集页查看元数据并打开正文，确认内容可读、查询串敏感项已掩码、正文文件权限仅限运行账户、审计页出现本次查看记录；随后把保留时间设为极小值触发清理，确认分段文件被回收且索引无悬空引用。

## 6. 风险与待定

- **风险**：高采集开启率下元数据批量写入可能放大 SQLite 写竞争。缓解方式是有界队列、批量提交与降级计数，并在 FR-14 观察写入延迟。
- **风险**：清理与写入并发可能短暂超过 5 GiB。缓解方式是容量接近阈值时提前触发清理并预留安全余量，超限期间对新请求按放弃正文但保留元数据处理。
- **风险**：明文正文落盘是已接受风险，数据目录或备份泄露即暴露业务内容。缓解方式是默认关闭、逐代理开启、30 天与 5 GiB 上限、审计与最小文件权限；文档与 UI 不得声称加密。
- **风险**：截断后正文不完整可能被误读为完整请求。缓解方式是元数据与界面都如实标记已截断。
- **待定**：分段文件大小上限的默认值需在压测后在此规格定稿，暂按可配置与有界实现。
- **待定**：正文在 Web 上的展示上限与截断策略需与 FR-11 采集页实现共同定稿。
- **待定**：一致性检查的执行时机（仅启动时、定时或清理后）取决于清理频率实测结果，暂定为启动时与每次清理后各执行一次。
