# 功能规格：运行监控指标

> 状态：草拟 · 关联 PRD：FR-14 · 分支：feature/monitoring-metrics

## 1. 背景与目标

管理员需要回答"现在系统是否健康"，而不是逐条翻日志。JRP 的运行状态分散在客户端连接、代理状态、连接与流量、错误、配置应用结果和采集容量七个方面，缺任何一类都会让故障定位变成猜测。

FR-14 解决三件事：

1. 用一套统一的指标模型覆盖七类监控对象，让 Web 状态页、管理 API 与运维检查看的是同一组数据。
2. 让指标可以来自 Core 的运行事件与只读状态快照，但**不反向依赖 Core 内部状态**，也不把观测通道变成数据面的负担。
3. 保证指标本身不构成泄露面：指标不得包含 token、密码、Cookie、Authorization 或完整正文。

使用者是管理员（Web 状态页）、运维检查（`/api/v1/status`、`/api/v1/metrics`）以及排障流程。属于 P1 阶段。数据面隔离见 ADR-0003，配置真源见 ADR-0004，事件与快照契约见 FR-27，本规格不重复其正文。

## 2. 需求

- 指标覆盖七类对象：**客户端、代理、连接、流量、错误、配置应用、采集容量**。每一类至少提供状态维度与计数或水位维度。
- 指标是聚合结果，不是事件流：指标回答"当前是什么水位、累计发生过多少"，历史明细归 FR-12 日志与 FR-16 审计。
- 指标不得包含 token、密码、Cookie、Authorization 或完整正文；客户端与代理维度只允许出现标识与名称。
- 指标来源以 Core 的有界类型化事件通道（FR-27）为主，以只读状态快照为校正与重建手段；适配器不得穿透读取 Core 内部状态。
- 事件通道溢出时，指标侧依据重同步要求调用只读状态快照重建视图，并如实反映"发生过溢出"，不得用旧值冒充当前值。
- 指标计算不得阻塞数据面：事件消费、聚合与快照读取都在数据面之外；慢消费只影响指标新鲜度，不影响转发。
- 采集容量是监控对象：正文总量、总量上限、已用比例、保留清理执行结果与最近清理时间必须可观测。
- 指标同时服务于 `/api/v1/status`、`/api/v1/metrics` 与 Web 状态页，三者共用同一聚合出口，不得各自按不同口径计算。
- 指标读取需要管理员会话；`/healthz` 与 `/readyz` 保持无认证，但不暴露详细指标。
- 规模基线为 200 在线客户端与 2000 代理（NFR）；指标聚合开销不得随代理数线性放大到不可接受，必要时按类别分页或摘要化。

- 范围内：
  - 七类指标的指标项定义、单位、聚合口径与重置语义。
  - Core 事件到指标的映射与只读快照校正路径。
  - 指标聚合出口与 `/api/v1/status`、`/api/v1/metrics` 的共享口径。
  - 采集容量指标的口径与上限对照。
  - 指标脱敏约束与读取访问控制。
  - 指标在事件溢出与进程重启后的重建语义。
- 范围外：
  - **配置文件作为配置真源**：已被 ADR-0004 拒绝；指标阈值与采集间隔只存 SQLite 并经管理 API 变更。
  - 告警规则引擎、告警抑制与升级策略：告警判定基线在本规格提供指标，规则化告警不在本范围。
  - 深度流量分析、请求内容分析、趋势预测与异常检测（P2）。
  - 外部监控系统对接、时序数据库、Prometheus 抓取端点与远程写入：抓取格式另由实现决策明确，不预设协议。
  - 多节点指标汇聚、集中式可观测后端与分布式追踪（P3）。
  - 按租户或按角色的指标可见性分级（P3）。
  - 指标历史持久化与长期时序存储：本功能提供当前值与累计计数，不做时序落库。

## 3. 设计

### 3.1 模块与依赖方向

- Core 侧：只通过 FR-27 的有界事件通道发布运行事件，并提供只读状态快照。Core 不做指标聚合、不定义指标模型、不暴露内部计数器。
- jrps 侧：持有指标聚合器，消费事件、按需调用只读快照、维护聚合状态，并向管理 API 与 Web 提供只读出口。
- jrpc 侧：维护本客户端自身的同类指标，输出到本地；不向服务端上报指标，也不从服务端拉取指标。
- 依赖方向：外壳 → Core 单向。聚合器是事件消费者，其消费延迟不得反向影响数据面（ADR-0003）。
- 指标模型、聚合器与管理 DTO 都是外壳私有类型，不得进入 Core。

### 3.2 七类指标

| 类别 | 指标项要点 | 单位与口径 |
|---|---|---|
| 客户端 | 在线客户端数、待 enrollment 客户端数、最近连接时间分布、按客户端的连接状态 | 计数与枚举状态；只含客户端标识与名称 |
| 代理 | 按类型的代理总数与就绪数、按代理的当前状态、变更次数 | 计数与枚举状态；只含代理名与类型 |
| 连接 | 控制会话数、工作连接数、按代理的活动连接数、连接建立与关闭累计 | 计数；连接不含对端凭证信息 |
| 流量 | 按代理与按方向的累计字节数、当前速率、峰值窗口 | 字节与字节每秒；不采样内容 |
| 错误 | 按类别的错误累计、最近错误时间与脱敏错误摘要、事件通道溢出丢弃计数、采集降级丢弃计数 | 计数与最近一次摘要 |
| 配置应用 | desired、active、last-good revision 摘要、最近一次应用阶段与结果、按阶段失败累计、最近应用耗时毫秒 | 版本标识、枚举阶段、计数与毫秒 |
| 采集容量 | 正文已用字节、上限字节、已用比例、元数据行数、最近清理时间与结果、孤儿段与缺失引用计数 | 字节、计数与时间 |

聚合口径统一约定：

- 累计计数在进程重启后从零开始，界面须如实标注"自进程启动以来"，不得冒充全量历史。
- 当前水位（在线数、活动连接数、正文用量）反映实时状态，可由只读快照校正。
- 速率类指标使用固定窗口计算，窗口长度在实现时定标并写入文档。

### 3.3 Core 事件到指标的映射

```text
Core 数据面 ──有界事件通道(FR-27)──▶ 外壳聚合器 ──▶ /api/v1/status、/api/v1/metrics、Web 状态页
                    │
                    └──溢出──▶ ResyncRequired ──▶ 聚合器调用只读状态快照重建水位
```

- 映射规则：客户端连接与断开事件更新在线客户端数与连接计数；代理状态变化更新代理状态；Apply 结果更新配置应用指标；停止事件标记指标停止更新。
- 脱敏在映射入口完成：事件载荷中的错误摘要已是安全可公开文本；映射层再执行一次字段白名单过滤，只允许标识、计数、枚举与时间进入指标。
- 指标不反向依赖 Core 内部状态：聚合器不得调用任何返回内部活对象或内部指针的接口，只能通过事件与只读快照取值。
- 溢出处理：收到重同步要求时聚合器用只读快照重建水位类指标，并记录一次溢出事件到错误类指标；累计计数因无法补齐而如实保持不完整，不伪造。

### 3.4 采集容量指标

采集容量指标直接对应 ADR-0007 与 FR-13 的 5 GiB 上限：

- 正文已用字节与上限字节，以及两者算出的已用比例。
- 元数据行数与最近清理执行结果（成功、部分成功、失败）。
- 最近清理时间与被回收分段数。
- 孤儿段计数与缺失引用计数，用于暴露索引与文件不一致。
- 单请求截断计数与超限放弃计数，用于暴露采集上限被频繁触发。

容量指标在接近上限时驱动 WARN 日志（FR-12）；是否触发通知由 FR-15 消费指标或事件决定，本功能只提供数据。

### 3.5 访问控制与输出

- `/api/v1/status` 与 `/api/v1/metrics` 需要管理员会话；未认证返回 401。
- `/healthz` 与 `/readyz` 保持无认证，只返回最小存活与就绪状态，不返回详细指标。
- 响应使用 UTF-8 JSON，时间使用 RFC 3339 UTC，字节用整数，持续时间明确带毫秒或秒后缀。
- 指标读取是只读 GET，不产生副作用，不要求 CSRF；响应不得包含任何未脱敏字段。
- 按代理或按客户端的明细列表支持游标分页；默认 `limit` 与最大值遵循 `docs/API.md` §1.5。

### 3.6 重启与并发

- 进程重启后水位类指标由只读快照重建，累计类指标归零并如实标注起点。
- 聚合器状态可并发读写；并发读取不得返回半更新聚合值。
- Web 状态页通过 SSE 观察状态变化（FR-11），不得通过 SSE 发送命令；SSE 背压不得传回 Core。

## 5. 验收标准

正常路径：

- 自动化：客户端连接后在线客户端数加一并反映连接状态；断开后减一，状态变更为离线。
- 自动化：代理就绪后按类型与状态的统计正确；代理变更触发的变更次数递增。
- 自动化：建立工作连接并收发数据后，连接计数与双向流量字节数与耗时窗口内的预期一致。
- 自动化：配置应用成功后 desired、active、last-good 摘要均正确推进；失败时按阶段失败累计递增且 active 不变。
- 自动化：采集开启并写入正文后，正文已用字节、上限与比例正确；清理执行后最近清理时间与回收分段数更新。
- 自动化：已登录管理员可读取状态与指标，响应字段与七类指标定义一一对应。

边界：

- 自动化：空状态（无客户端、无代理、无采集数据）时指标均为零值或明确空标记，不返回空响应体错误。
- 自动化：按代理或客户端的明细列表在超过一页时返回 `nextCursor`，末页不返回游标。
- 自动化：进程重启后水位类指标由只读快照重建，累计类指标归零并标注"自进程启动以来"。
- 自动化：在 200 客户端与 2000 代理的规模基线场景下，聚合读取耗时在既定容差内（容差数值由 FR-14 压测定稿后补齐，补齐前不作为门禁），不随代理数线性放大。
- 自动化：并发读取聚合值不返回半更新结果；`-race` 下无竞态报告。

错误路径：

- 自动化：指标输出中不含 token、密码、Cookie、Authorization 或完整正文；对这五类值逐一构造用例断言。
- 自动化：事件通道溢出后收到重同步要求时，水位类指标由只读快照重建，错误类指标记录一次溢出，且不伪造累计计数。
- 自动化：Core 停止后指标停止更新并保留最后已知值，不返回错误也不清空。
- 自动化：只读快照不可用或返回错误时，指标标记 degraded 并记录 ERROR 日志，不影响数据面转发。
- 自动化：未认证访问 `/api/v1/status` 与 `/api/v1/metrics` 返回 401；`/healthz` 与 `/readyz` 仍无认证且不返回详细指标。
- 自动化：聚合器代码中不存在读取 Core 内部活对象、内部指针或 `internal` 类型的路径。

实机（需用户确认）：在一台机器上启动 jrps 并接入一个 jrpc 或官方 frpc，建立若干代理并持续跑流量十分钟；在 Web 状态页核对客户端、代理、连接、流量、错误、配置应用与采集容量七类指标与命令行实测值一致；期间人为制造一次配置应用失败与一次通知失败，确认错误类指标递增且摘要为中文脱敏文本。

## 6. 风险与待定

- **风险**：事件通道溢出会让累计类指标不完整。缓解方式是如实记录溢出次数并在界面标注，配合只读快照重建水位，不假装完整。
- **风险**：2000 代理规模下聚合与深复制快照的开销可能偏高。缓解方式是压测后按类别摘要化或分页读取，具体形态以实测结论定稿。
- **风险**：累计计数随重启归零可能被误读为历史丢失。缓解方式是界面与 API 明确标注起点，历史明细依赖日志与审计。
- **风险**：速率窗口选择不当会掩盖突发流量。缓解方式是同时保留累计字节与峰值窗口，窗口长度在实测后定标。
- **待定**：速率计算窗口长度、指标刷新周期与快照校正频率的具体数值需在压测后在此规格定稿，暂按固定窗口与有界频率实现。
- **待定**：`/api/v1/metrics` 是否额外提供机器抓取格式，取决于运维集成方式的后续确认；未确认前只提供 JSON 摘要。
- **待定**：Web 状态页的指标字段集合需与 FR-11 页面实现对齐后统一。
