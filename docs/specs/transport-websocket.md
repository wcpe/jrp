# 功能规格：WebSocket 与 WSS 连接传输

> 状态：草拟 · 关联 PRD：FR-05b · 分支：feature/transport-websocket

## 1. 背景与目标

FR-05b 要求 Core 支持 WebSocket 与 WSS 两种连接传输。部署实践中，官方 frpc 常常需要穿越只放行 HTTP/HTTPS 的反向代理或企业网关，此时纯 TCP 传输不可用，而基于 HTTP 升级的 WebSocket 可以复用既有入口。WSS 在此之上叠加 TLS，用于公网路径上的机密性与完整性保护。

本规格解决的具体问题是：在复用 FR-05a 已建立的传输抽象形状的前提下，把 WebSocket 的「HTTP 升级握手 + 分帧消息流」适配成面向流的连接语义，并处理 WSS 引入的 TLS 配置、证书校验与握手失败路径。使用者：Core 传输接入层、jrps 装配层，以及嵌入 Core 的宿主。所属阶段：P1。

## 2. 需求

- 支持 WebSocket（明文）连接传输：服务端在同一 HTTP 入口上接受升级请求，客户端发起升级建链。
- 支持 WSS：在 WebSocket 之下叠加 TLS，服务端可配置证书与密钥来源，客户端可配置证书校验策略（含自签名场景的指纹固定）。
- 传输层向上呈现面向流的连接语义，与 FR-05a 的传输抽象形状一致，使会话层无需感知底层是 TCP 还是 WebSocket。
- 握手失败、分帧异常、消息超限、TLS 错误必须有确定处理路径，不悬挂、不泄漏。
- 生命周期可判定：关闭后无残留监听器、连接或 goroutine。
- 传输公共接口只暴露标准库类型与 Core 自有值类型，**不得泄漏第三方实现类型**。

- 范围内：WebSocket 服务端升级与客户端拨号、WSS 的 TLS 配置与证书校验、分帧到流语义的适配、超时与关闭、异常路径资源回收、与既有 HTTP 入口的复用关系。
- 范围外：
  - **「JRP 客户端连接官方 frps」这一反向兼容方向，本轮不做**，本规格不承载任何反向兼容承诺。
  - TCP 传输（FR-05a）、KCP 与 QUIC 传输（FR-05c）。
  - JRP 私有管理通道的 WSS 长连接（属于 FR-08，走 `/agent/v1` 独立通道，与本规格的数据面传输路径分离）。
  - 管理 API 的 HTTPS 监听与证书治理（属于 jrps 外壳职责）。
  - P2 的 TLS 终止后 HTTPS 正文采集（FR-21）。
  - P3 的数据节点、节点 RPC、选举、分布式锁、共享数据库、租户、RBAC、OIDC。

## 3. 设计

### 3.1 依赖策略（待批准）

WebSocket 的分帧与握手需要一个成熟实现。按项目依赖管理规范，引入第三方依赖必须先说明理由并等待确认。本规格声明的候选依赖是 `golang.org/x/net`（用于其 WebSocket 实现）。

**该依赖尚未获批；在获批之前不启动本规格任何实现工作。** 依赖获批前允许的前置动作只有：完成本规格评审、确定抽象形状与验收口径、以及用 FR-05a 已有抽象验证形状假设。

获批后需遵守的约束：

- 依赖只允许出现在 Core 的传输包内，不得扩散到协议模型、会话层或代理层。
- 依赖版本范围由 `core/go.mod` 显式声明，禁止静默引入破坏性更新。

### 3.2 传输抽象与类型隔离

WebSocket 传输实现 FR-05a 定义的同一传输抽象：监听、拨号、连接、用途标记。差异只在内部实现：

- 监听侧：在既有或独立的 HTTP 入口上注册升级路径，把升级成功的连接适配为流语义。
- 拨号侧：发起升级请求，成功后返回同样的连接句柄。

**类型隔离是硬性设计约束**：Core 的公共接口与传输抽象签名中不得出现 WebSocket 库的连接、分帧或握手类型。第三方类型只允许出现在传输包内部的私有字段与局部变量中。这直接对应 NFR「Core 公共接口只暴露标准库类型与 Core 自有值类型，不泄漏第三方实现类型」。

### 3.3 WebSocket 服务端侧

- 升级请求必须校验：路径匹配、方法、必要头字段、来源策略。
- 校验失败的升级请求按 HTTP 语义返回明确状态码，不升级为连接。
- 升级成功后连接进入与 TCP 相同的生命周期管理：读超时由上层驱动、写超时由上层驱动、关闭两阶段。
- 分帧到流的适配要点：消息边界由底层分帧承载，对上层只呈现连续字节流；上层不得依赖分帧边界传递协议边界（协议边界由 wire 层负责）。
- 单条消息大小必须有上限，超过上限的分帧序列立即终止连接并释放资源，禁止按对端声明长度无界分配。

### 3.4 WebSocket 客户端侧

- 拨号必须带超时；握手响应校验（状态码、必要头字段）失败即返回错误，不重试到底。
- 支持配置请求头（用于身份或路由提示），但禁止在头中携带 token 明文或完整正文。
- 建链成功后连接句柄与服务端侧同构。

### 3.5 WSS 与 TLS

- 服务端侧：证书与密钥来源由配置快照提供；支持证书链文件与密钥文件，也支持嵌入宿主注入的 TLS 配置对象（仍以标准库类型表达）。
- 客户端侧：默认按系统信任链校验；自签名与私有 CA 场景支持指纹固定或指定信任根，**默认不关闭校验**。
- TLS 握手失败（证书过期、域名不匹配、信任链失败、协议版本不支持）必须返回稳定错误类别，关闭连接，日志与事件不回显私钥或完整证书内容。
- 引导参数约束：TLS 监听地址属于运行配置，其变更走 Core 的配置应用流程；证书文件路径是否属于需重启的引导参数由 jrps 外壳的既有约定决定，本规格不自创规则。

### 3.6 与既有 HTTP 入口的关系

WebSocket 需要占用一个 HTTP 入口的升级路径。设计选择：

- 允许与 jrps 的 HTTP 入口共存，但**必须路径隔离**：兼容数据面的升级路径与管理 API、健康检查路径不重叠。
- 也允许配置独立监听，用于隔离数据面与管理面的故障域。
- 两种方式的取舍（路径 vs 端口）由部署形态决定，不由 Core 强制。

### 3.7 异常路径

| 异常类别 | 处理 |
|---|---|
| 升级请求校验失败 | 返回明确 HTTP 状态码，不建立连接 |
| 分帧序列非法 | 关闭连接，释放缓冲 |
| 消息超过上限 | 终止连接，不分配声明长度的内存 |
| 对端关闭帧 | 按正常关闭处理，走两阶段关闭 |
| TLS 握手失败 | 返回稳定错误类别，关闭连接，不回显私钥或证书全文 |
| 读写超时 / 上下文取消 | 中断阻塞 IO，释放连接与 goroutine |
| 拨号失败 | 返回错误，重试策略由上层控制 |

### 3.8 与 ADR 的关系

- Core 模块边界、禁止依赖方向与「Core 只承载数据面能力」遵循 ADR-0002 与 ADR-0003。
- 无中断配置应用对监听资源的接管与释放语义遵循 ADR-0005。
- 兼容实现的独立性与固定基线遵循 ADR-0010（取代 ADR-0001），本规格不重复其决策正文。

## 5. 验收标准

正常路径：

- 固定基线官方 frpc 以 WebSocket 传输完成登录、心跳、代理注册与工作连接转发。
- 固定基线官方 frpc 以 WSS 传输完成同样流程，TLS 握手成功且数据双向可达。
- 服务端可在同一 HTTP 入口上与既有路径共存，路径隔离生效。
- 连接句柄与 FR-05a 的连接语义一致，会话层无感知差异。

边界：

- 消息大小等于上限、上限加一、上限减一的行为分别为接受、拒绝、接受。
- 零长度消息、连续小消息、单条大消息均正确传输。
- 客户端在自签名证书场景下通过指纹固定建链成功；未配置指纹时校验失败并被拒绝。

错误路径：

- 升级请求路径不匹配、方法不符、必要头缺失时返回明确状态码且不建链。
- 分帧非法、消息超限、对端异常关闭帧均关闭连接并释放资源。
- TLS 握手失败的四类原因（过期、域名不匹配、信任链失败、协议版本不支持）均返回稳定错误类别，不回显私钥或证书全文。
- 关闭完成后 goroutine 与连接计数归零。

类型隔离：

- 传输抽象与 Core 公共接口的签名审计测试通过：不出现 WebSocket 库的任何类型。
- 第三方类型仅出现在传输包内部，不跨包传播。

实机：

- 真实网络（跨公网、经过反向代理或企业网关）下的 WebSocket 与 WSS 稳定性、重连与吞吐需用户在目标环境确认实机通过；本地与 CI 测试不能替代真实网络验收。
- 经过中间 HTTP 代理时的升级兼容性需用户实机确认。

## 6. 风险与待定

- **依赖待批准引入，批准前不启动实现**：本规格所需能力依赖 `golang.org/x/net`。该依赖**尚未批准**，在获得明确批准之前，本规格的第 4 节实现类任务一律不启动，只维持规格与验收口径的评审状态。获批后须先在 `core/go.mod` 显式声明版本范围，再进入实现。
- **依赖只允许出现在传输包内**：若评审发现第三方类型难以完全隔离在私有字段中，需重新评估抽象形状并新增 ADR，不得放宽类型隔离约束。
- **自签名指纹固定的安全边界**：指纹固定会降低对证书链的依赖，必须与 SECURITY 文档口径一致，不得声称其等价于完整 PKI 校验。
- **与既有 HTTP 入口的路径冲突风险**：若未来管理面路径调整，可能引入路径重叠，需要在配置校验阶段显式拒绝重叠路径。
- **真实网络行为需实机确认**：穿越企业网关、反向代理与负载均衡时的升级成功率、空闲断链与重连行为无法由本地测试证明。
- **FR-05c 依赖同样待批准**：本规格与 FR-05c 的完成顺序会影响传输抽象是否需要二次调整，建议先完成本规格再回头校验抽象。
