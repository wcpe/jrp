# 功能规格：wire v1 与 wire v2 编解码

> 状态：草拟 · 关联 PRD：FR-04 · 分支：feature/wire-v1-v2-codec

## 1. 背景与目标

官方 frpc 与 JRP jrpc 都通过一个带版本号的线上封装（下文统称 wire）向服务端提交控制消息与工作连接数据。FR-04 要求 Core 同时支持 wire v1 与 wire v2，并且协商、降级、拒绝三种行为都必须可判定、可观测、可测试。

本规格解决的具体问题是：一条来自未知实现的连接，其开头几个字节可能属于 v2 版本魔数，也可能已经是 v1 的消息。Core 必须在**不消耗已读字节**的前提下判定版本，并在判定后给出确定答案：接受、拒绝、或在合法前提下降级。模糊不清的兼容行为会直接放大为连接悬挂、goroutine 泄漏和难以归因的数据面故障，因此本规格把「绝不静默」作为第一原则。

使用者：Core 的控制会话、工作连接建立路径，以及依赖 Core 的 jrps / jrpc 外壳与嵌入宿主。所属阶段：P1。

## 2. 需求

- 支持在同一服务端端口上同时接收 wire v1 与 wire v2 连接。
- 版本判定必须使用带回放能力的预读缓冲：判定为 v1 时，已预读字节必须作为 v1 消息的一部分被完整解析，不得丢弃或猜测。
- v2 协商必须显式达成：帧格式版本、消息编码方式、加密算法、可选压缩算法、单帧载荷上限。
- 降级只允许发生在「连接未声明必须使用 v2」且「v2 握手未能被识别」的兼容路径上；显式要求 v2 时的协商失败必须失败。
- 拒绝必须可判定：返回稳定错误类别、记录可观测事件、关闭连接并释放资源，不得悬挂或对端等待超时。
- 加密与压缩的启用、变更、关闭必须走受限状态机，非法迁移一律拒绝而不是自动纠正。
- 所有长度类字段必须有上限，禁止按对端声明值进行无界内存分配。
- well-formed 黄金帧必须可重复编解码；畸形输入不得导致 panic、无界分配、死锁或资源泄漏。

- 范围内：v1 与 v2 的帧解析与序列化、版本判定与预读回放、v2 hello 协商、降级判定、拒绝语义、加密/压缩状态机、载荷上限、黄金帧与畸形输入测试。
- 范围外：
  - 「JRP 客户端连接官方 frps」这一反向兼容方向，本轮不做，也不作为任何设计约束。
  - 具体传输协议（TCP / WebSocket / WSS / KCP / QUIC）的建链细节，见 FR-05a / FR-05b / FR-05c 规格。
  - 登录、心跳、代理注册等会话层语义，见 FR-03 规格。
  - 任何 JRP 私有管理命令不得进入 wire 承载能力（ADR 边界见 §3）。

## 3. 设计

### 3.1 分层与依赖方向

wire 层位于消息层之下、传输层之上，只依赖标准库的 `encoding/binary`、`encoding/json`、`io`、`hash`、`crypto` 系列，不依赖任何传输实现类型，也不感知具体传输协议。这与 `docs/PROTOCOL.md` §2 的分层一致；理由是 wire 层要被所有传输共用，一旦向下感知具体传输，传输选型就会反向绑进编解码热路径。

Core 内部职责划分按 `docs/ARCHITECTURE.md` §2.1 的「wire v1/v2 编解码、协商和加密状态机」条目承担，不新增空包。

### 3.2 版本判定与预读回放

服务端在连接建立后立即包一层带回放能力的读取器，读取固定宽度的前导字节：

1. 前导字节等于 JRP 记录的 v2 版本魔数 → 进入 v2 hello 协商。
2. 前导字节不等于该魔数 → 把**全部已读字节**（含前导）回放到流的前端，进入 v1 兼容路径。
3. 前导字节不足且连接已结束（EOF）→ 判定为「空连接」，直接关闭，不计为协议错误也不计为成功。

回放是本设计的关键点：v1 没有独立的版本魔数，如果对 v2 魔数判定失败就消费掉前导字节，v1 解析将永久错位。因此「预读 + 回放」是硬性要求，任何「先读取再判断」的写法都必须保证已读字节可被完整回放。

### 3.3 wire v1 帧单元

每条 v1 消息是一个自描述的帧单元，依次由三部分组成：

| 片段 | 宽度 | 语义 |
|---|---:|---|
| 消息类型 | 1 字节 | 已定义的兼容消息类型枚举 |
| 载荷长度 | 8 字节网络字节序 | 有符号整数，紧随其后的 JSON 载荷字节数 |
| 载荷 | 变长 | UTF-8 JSON 对象 |

解析约束遵循 `docs/PROTOCOL.md` §3：

- 载荷长度不得超过运行时上限，超限立即返回协议错误并关闭连接。
- 类型字节缺失、长度字段缺失、长度字段为负值、载荷不足或多余，均为协议错误。
- 未知消息类型返回「不支持类别」错误并关闭受影响连接。
- JSON 解码失败视为协议错误；未知 JSON 字段在不影响语义与安全的前提下忽略，不回显、不提升为 JRP 管理配置。

### 3.4 wire v2 帧头与 hello 协商

v2 帧头固定为 8 字节网络字节序，字段定义与约束见 `docs/PROTOCOL.md` §4.1，此处不重复。P1 只接受 flags 为 0 的帧，非零 flags 一律拒绝，理由是 P1 尚未定义任何 flags 位的语义，接受未知位等同于接受未知行为。

hello 载荷按黑盒取证确认的**嵌套结构**承载能力：client hello 的能力集合位于 `capabilities` 之下（`message.codecs`、`crypto.algorithms`、可选的 `compression.algorithms`、`maxPayload`，以及 `bootstrap` 传输摘要）；server hello 的选定结果位于 `selected` 之下（`message.codec`、`crypto.algorithm`、可选的 `compression.algorithm`、`maxPayload`）。协商材料（如对端随机值）只在协商期内使用，不得进入协商结果、事件或日志。

协商流程严格按 `docs/PROTOCOL.md` §4.2 的六条规则落地：

1. 客户端写入 v2 魔数后发送 client hello，载荷声明其支持的编码、加密、压缩算法集合与传输/TLS 复用摘要。
2. 服务端按自身已交付能力求交集：
   - 消息编码：P1 唯一可选值为 JSON，交集为空则协商失败。
   - 加密：P1 支持「不加密」与一种对称流加密；交集为空则协商失败。
   - 压缩：可选，无交集时退化为不压缩而非失败。
   - 单帧载荷上限：取双方声明的较小值，且不得高于 Core 自身的实现上限。
3. 服务端返回 server hello 承载协商结果，或返回「安全可公开的失败原因」并关闭连接。失败原因只含类别信息，不回显密钥材料、内部字段路径或完整对端载荷。
4. 连接一旦选定 wire 版本，在该连接生命周期内不允许切换版本。v2 连接上出现 v1 前导、或已判为 v1 的连接上出现 v2 魔数，均为协议错误。

### 3.5 降级与拒绝的判定表

降级不是「v2 解析出错就改 v1」。本规格把降级收窄为唯一合法路径：**前导字节未被识别为 v2 魔数**，且连接未显式声明「必须 v2」。

| 情形 | 服务端行为 |
|---|---|
| 前导非 v2 魔数，对端未声明必须 v2 | 回放字节，按 v1 解析（合法降级） |
| 前导非 v2 魔数，但对端在 out-of-band 接入方式上被管理员配置为「仅 v2」 | 拒绝，错误类别「版本不被接受」 |
| 前导为 v2 魔数，hello 能力交集为空 | 拒绝，错误类别「能力无法协商」（**禁止**静默降 v1） |
| 前导为 v2 魔数，hello 帧格式非法或超时 | 拒绝，错误类别「协商帧非法」 |
| 前导为 v2 魔数，但 v2 支持在服务端整体关闭 | 拒绝，错误类别「版本不被接受」 |
| 协商成功 | 锁定 v2 + 协商结果，进入消息层 |

「必须 v2」的来源是服务端自身的运行配置：jrps 可以为不同监听入口声明允许的最低 wire 版本。这是兼容协议之外的本地决策，不需要对端配合，也不写进任何协议消息。

所有拒绝路径都统一经过一个出口：记录含 wire 阶段标记、错误类别与对端地址摘要的连接关闭事件（地址与身份均脱敏），随后关闭底层连接。禁止出现「既不成功也不关闭」的中间状态。

### 3.6 加密与压缩状态机

控制连接与每条工作连接各自持有一份变换状态机，两类的合法迁移路径相同：

```text
裸连接 ──启用加密──▶ 已加密 ──启用压缩──▶ 已加密＋已压缩
裸连接 ──启用压缩──▶ 已压缩 ──启用加密──▶ 已加密＋已压缩
```

迁移规则：

- 每种变换只能**启用一次**，重复启用同一变换视为协议错误。
- 启用顺序可自由组合，但每种变换在协商成功时就已确定是否可用；不在协商结果中的算法不允许在运行时启用。
- 已建立的变换**不可关闭、不可更换参数**。连接中途要求更换密钥参数一律拒绝。
- 处于中间态一律回收：密钥派生失败、算法参数校验失败、写入部分成功后出错，都必须关闭连接而不是退回裸连接。
- 加密启用前不得向连接写入任何应用载荷。

### 3.7 边界与畸形帧处理

统一原则：**先校验长度，再分配内存；先校验类型，再解析载荷**。

| 畸形类别 | 处理 |
|---|---|
| 帧头长度超协商/实现上限 | 协议错误，关闭连接，不分配该长度的缓冲区 |
| 长度为负值等不可能取值 | 协议错误，关闭连接 |
| 载荷截断（连接中途 EOF / 半关闭） | 停止解析，释放已分配缓冲与临时状态，关闭连接 |
| 载荷多于声明长度 | 按边界切开；多余部分视为下一帧，若下一帧非法则关闭 |
| 消息类型长度为 0 或少于类型宽度 | 协议错误 |
| 未知消息类型 ID | 类型错误，关闭受影响连接 |
| 非法帧类型、非零未知 flags | 拒绝当前连接 |
| JSON 结构畸形 | 协议错误，不重试、不补猜 |

所有缓冲区从有界池中分配并显式归还，禁止在热路径对每个消息做独立大块分配。

### 3.8 与 ADR 的关系

- 兼容研究的独立实现边界与固定 Git 提交基线遵循 ADR-0010（取代 ADR-0001），本规格不重复其决策正文。
- Core 模块边界与禁止依赖方向遵循 ADR-0002。
- 本规格不得引入任何参考仓库的注释、错误文案、目录结构或测试组织；所有 wire 表述以 JRP 自有规格与黑盒取证为准。

## 5. 验收标准

正常路径：

- v1 连接发送一条合法登录消息可完成编解码往返；编码器输出与解码器输入互为逆运算，字节级可重复。
- v2 连接完成 hello 协商后，消息帧在 JSON 编码下往返一致；协商结果中的载荷上限被双向约束。
- 同一服务端端口分别接入 v1 与 v2 连接，两者互不影响，版本判定正确。

降级与拒绝：

- 前导字节非 v2 魔数时，已预读字节被完整回放，v1 首帧能正确解析出预期消息类型与载荷。
- 显式要求 v2 的连接在 hello 能力交集为空时被拒绝，且服务端不回落 v1：断言连接关闭且事件中的 wire 阶段标记为协商阶段。
- 每种拒绝情形都能观测到结构化关闭事件，且事件不含对端完整载荷、密钥材料或内部字段路径。
- 不存在「对端既未收到成功也未收到关闭」的路径：所有拒绝分支在超时阈值前完成关闭。

边界：

- 载荷长度等于上限、等于上限加一、等于上限减一时行为分别为接受、拒绝、接受。
- 长度为负值等不可能取值被拒绝且不触发分配。
- 载荷逐字节截断的每个前缀都得到明确错误而非悬挂。
- 单条连接上连续发送多种畸形帧时，连接在第一次协议错误时关闭，不泄漏 goroutine 与缓冲。

错误路径：

- 重复启用同一变换、在未协商算法上启用、中途更换密钥参数，三种迁移均被拒绝。
- 加密协商成功后才允许应用载荷：断言启用前的应用写入被拒绝。

模糊与实机：

- 以自建畸形输入语料做模糊入口测试（含全零、全 0xFF、随机字节、随机合法帧变形），无 panic、无无界分配、无死锁、无资源泄漏。
- 黄金帧覆盖政策见 §5.1。
- 涉及真实网络（长肥管道、乱序、半关闭）下的 v2 连接行为，需用户在真实网络环境确认实机通过；测试全绿不能替代实机验收。

### 5.1 黄金帧测试设计思路

不穷举所有字段组合，采用分层取样策略，目的是用最少的向量覆盖最多的解析分支：

1. **字节层**：为每种字段宽度和字节序准备最小、上限、上限减一、上限加一四组值，证明边界切分正确。
2. **类型层**：每个已支持的消息类型一个代表帧（正常载荷）+ 一个异常变体（类型剪短或不存在的类型值），覆盖「类型决定解析策略」的分支，不为每个类型乘字段子集。
3. **状态层**：对每个状态机迁移准备「从合法前态出发」的一组帧，以及「从非法前态出发」的一组帧，证明迁移合法性判定而非 payload 内容校验。
4. **向量回流层**：从真实官方 frpc 黑盒运行中抽取若干观测样本，提炼成 JRP 自有向量，只保留行为等价部分，不引入外部测试数据组织方式。
5. **回归层**：向量以文件形式纳入 Core 测试资产，任何 wire 变更必须显式更新向量并说明理由，禁止静默调整通过。

## 6. 风险与待定

- **v1 载荷长度字段已完成取证**：对固定基线的只读线上行为核对确认，长度字段为 **8 字节有符号整数、网络字节序**；载荷上限存在默认值且属实现上限而非协议常量。`docs/PROTOCOL.md` §3 与本规格 §3.3 已按取证结果更新。实现不得再按 4 字节或无符号解释，也不得静默兼容两种布局。
- **v2 魔数已完成取证**：对固定基线官方 frpc 的只读黑盒抓包确认，魔数为 **7 字节 `FRP\x00\x02\r\n`**，是连接级前缀而非帧的一部分。按「7 字节魔数 + 8 字节帧头」解析可对实测字节流完美平铺；按 8 字节魔数解释则首帧立即越界。`docs/PROTOCOL.md` §4 已按取证结果更新。实现不得按 8 字节魔数解释，也不得静默兼容两种宽度。
- **加密算法选择未定**：P1 只承诺一种对称流加密，具体算法与密钥派生需要在完整会话规格落地前确认；本规格只约束状态机形状，不锁定算法。
- **「仅 v2」入口策略的长期表达**：当前由服务端本地配置表达，未来若需要在协议层传递版本偏好，必须走新的 ADR，不得向 hello 载荷塞私有字段。
- **实机验收依赖网络条件**：涉及真实网络延迟、乱序与半关闭的行为需要用户在目标环境复核，CI 无法证明。
