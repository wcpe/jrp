# 功能规格：KCP 与 QUIC 连接传输

> 状态：草拟 · 关联 PRD：FR-05c · 分支：feature/transport-kcp-quic

## 1. 背景与目标

FR-05c 要求 Core 支持 KCP 与 QUIC 两种连接传输。两者的价值场景不同：KCP 以牺牲带宽换取弱网下的延迟稳定性，适合丢包率高的跨境或移动网络；QUIC 在 UDP 之上提供内建加密、多路复用与连接迁移，适合需要抗抖动、快速重连与单端口多流的路径。

本规格解决的具体问题是：这两种传输的语义与 TCP 差异很大（KCP 是可靠 UDP 承载，QUIC 是面向流与数据报的复合会话），如果直接把它们塞进面向流的传输抽象，很容易把第三方概念泄漏到 Core 的公共接口与会话层。因此本规格的核心不是「如何调用库」，而是「如何在引入两个第三方实现的同时维持 Core 的类型隔离与生命周期可判定性」。使用者：Core 传输接入层、jrps 装配层与嵌入宿主。所属阶段：P1。

## 2. 需求

- 支持 KCP 传输：服务端监听 UDP 端口并提供可靠字节流，客户端拨号建立 KCP 会话。
- 支持 QUIC 传输：服务端监听 UDP 端口并提供其上的流承载，客户端拨号建立会话。
- 两种传输都必须适配成与 FR-05a 一致的传输抽象形状，使会话层无感知差异。
- **Core 公共接口不得泄漏 QUIC / KCP 第三方实现类型**；第三方类型只允许出现在传输包内部。
- 握手失败、会话超时、对端迁移、TLS/加密错误、UDP 端口不可达必须有确定处理路径。
- 生命周期可判定：关闭后无残留监听器、会话、流或 goroutine。
- 传输层参数（窗口、重传、加密套件、空闲超时）来自配置快照，不在代码中写死。

- 范围内：KCP 与 QUIC 的服务端监听、客户端拨号、会话/流到连接语义的适配、参数配置、异常路径与资源回收、类型隔离约束。
- 范围外：
  - **「JRP 客户端连接官方 frps」这一反向兼容方向，本轮不做**，本规格不承载任何反向兼容承诺。
  - TCP 传输（FR-05a）、WebSocket 与 WSS 传输（FR-05b）。
  - QUIC 数据报（datagram）承载的专有语义与任何 P2 传输扩展。
  - P2 的 SUDP 与 TCPMUX（FR-18）。
  - P3 的数据节点、节点 RPC、选举、分布式锁、共享数据库、租户、RBAC、OIDC。

## 3. 设计

### 3.1 依赖策略（已批准）

KCP 与 QUIC 使用 `kcp-go/v5` 与 `quic-go`，用户已在 2026 年 9 月 26 日批准引入。依赖已锁定在 `core/go.mod`，只出现在 Core 传输适配包内；公共 API 不暴露第三方会话、流或配置类型。

需遵守的约束：

- 依赖只允许出现在 Core 的传输包内，不得扩散到协议模型、会话层、代理层。
- 版本范围由 `core/go.mod` 显式声明，禁止静默引入破坏性更新。
- 两个依赖互不感知，不得出现彼此类型的交叉引用。

### 3.2 类型隔离（本规格的核心约束）

NFR 明确要求：「Core 公共接口只暴露标准库类型与 Core 自有值类型，不泄漏 Gin、GORM、SQLite、QUIC/KCP 第三方实现类型或 internal 类型」。本规格把该要求落成三条可执行规则：

1. **接口签名规则**：传输抽象的监听、拨号、连接方法签名中只出现标准库类型（`net.Listener`、`net.Conn`、`context.Context`、`netip.AddrPort`）与 Core 自有值类型（用途标记、限制参数、结果类型）。出现任何一个第三方类型即为违规。
2. **适配层规则**：每种传输实现一个内部适配器，把第三方会话/流对象包装为私有字段持有的标准库连接语义。适配器不导出第三方类型，也不返回第三方对象。
3. **审计规则**：Core 增加接口签名审计测试，对公共包的导出符号做类型扫描，断言不含第三方类型。该测试是 FR-05c 的验收门禁之一，不是可选检查。

### 3.3 语义差异与适配策略

两种传输与面向流的 TCP 语义存在本质差异，适配时必须明确取舍：

| 维度 | KCP | QUIC |
|---|---|---|
| 底层承载 | UDP 之上的可靠字节流 | UDP 之上的加密会话，含多条流 |
| 与传输抽象的关系 | 一个 KCP 会话 = 一条连接 | 一个 QUIC 会话可承载多条流 |
| 加密 | 可选，与会话绑定 | 内建于会话，不可关闭 |
| 连接迁移 | 不支持 | 支持，对端地址可变 |

适配决策：

- **KCP**：一个 KCP 会话直接映射为一条连接；控制连接与每条工作连接各自建立会话（与官方 frpc 在该传输上的既有行为一致，此点由黑盒取证确认而非照抄实现）。
- **QUIC**：一个 QUIC 会话映射为一条连接；P1 不使用同一会话内的多流复用承载多条独立连接，保持与传输抽象「一个句柄一条连接」的形状一致，避免会话层需要理解流 ID。
- **连接迁移**：QUIC 迁移发生时，传输层更新对端地址摘要并产生可观测事件；上层不得依赖对端地址做身份判定（身份由会话层鉴权决定）。

### 3.4 KCP 设计要点

- 服务端监听 UDP 端口，按对端地址识别会话；新会话的产生与回收受上限约束，防止 UDP 放大与伪造源攻击面。
- 客户端拨号带超时；握手未完成时不得宣告建链成功。
- 会话参数（发送/接收窗口、重传策略、是否启用加密、MTU 相关上限）来自配置快照。
- 空闲会话在空闲上限后回收；回收时释放缓冲与 goroutine。
- 单会话的读写不得在持有全局锁时执行。

### 3.5 QUIC 设计要点

- 服务端监听 UDP 端口，接受会话并完成其内建的 TLS 握手；证书与密钥来源由配置快照提供，与 WSS 共用同一套 TLS 配置表达方式（仍以标准库类型表达）。
- 客户端校验服务端证书；自签名场景支持指纹固定或指定信任根，默认不关闭校验。
- 空闲超时与握手超时来自配置快照。
- 会话关闭与流关闭必须区分：会话关闭释放全部资源，单条流关闭不得误释放会话。
- 迁移事件、0-RTT 相关行为：P1 不启用 0-RTT；迁移支持由对端发起，服务端只观测不主动发起。

### 3.6 异常路径

| 异常类别 | 处理 |
|---|---|
| UDP 端口被占用或不可达 | 监听失败上报，不降级到其他端口 |
| KCP 握手超时 | 返回错误，释放会话与 goroutine |
| QUIC 握手失败（证书、版本、ALPN） | 返回稳定错误类别，关闭会话，不回显私钥或证书全文 |
| 会话空闲超时 | 回收会话，产生可观测事件 |
| 对端地址迁移（QUIC） | 更新地址摘要并产生事件，身份判定不受影响 |
| 单条流异常关闭 | 释放该流，不影响会话内其他资源 |
| 上下文取消 | 立即中断阻塞 IO 并释放资源 |

### 3.7 与 ADR 的关系

- Core 模块边界、禁止依赖方向与「Core 只承载数据面能力」遵循 ADR-0002 与 ADR-0003。
- 无中断配置应用对监听资源的接管与释放语义遵循 ADR-0005。
- 兼容实现的独立性与固定基线遵循 ADR-0010（取代 ADR-0001），本规格不重复其决策正文。
- 若类型隔离在实现中无法维持，必须先新增 ADR 再改变约束，不得静默放宽。

- [x] **QUIC 连接迁移**：规格 §3 要求「迁移发生时传输层更新对端地址摘要并产生可观测事件；上层不得依赖对端地址做身份判定」。实现为传输包内的迁移观测——迁移由 quic-go 在库内完成（连接 ID 与 TLS 状态在路径变化下保持不变，`RemoteAddr()` 自动反映新路径），传输层在读写路径上比较地址摘要，变化即产出 `PeerMigrated` 事件（载荷只含前后摘要，不含完整地址）。身份判定不引入地址维度：对端身份由会话层鉴权在登录时确定并绑定运行 ID，地址变化不改变身份，因此地址伪装无法被当作合法身份。

## 5. 验收标准

正常路径：

- 固定基线官方 frpc 以 KCP 传输完成登录、心跳、代理注册与工作连接转发。
- 固定基线官方 frpc 以 QUIC 传输完成同样流程，会话内建加密生效且数据双向可达。
- 两种传输的连接句柄与 FR-05a 的连接语义一致，会话层无感知差异。

类型隔离（硬性门禁）：

- 接口签名审计测试通过：Core 导出符号中不出现 `kcp-go` 或 `quic-go` 的任何类型。
- 第三方类型仅出现在传输包内部的私有字段与局部变量中，不跨包传播，不出现在错误值或事件载荷中。
- 错误与事件载荷只含稳定错误类别与脱敏后的对端地址摘要，不含第三方对象。

边界：

- 会话数达到上限时新会话被拒绝并有可观测事件，不悬挂。
- 空闲超时边界（等于超时、超时加一秒）行为可判定。
- KCP 在高丢包注入场景下仍保持可用，且吞吐退化幅度在记录的容差内。
- QUIC 会话内单条流关闭不影响会话与其他流（若 P1 场景内存在多条流）。

错误路径：

- UDP 端口占用、KCP 握手超时、QUIC 四类握手失败（证书、版本、ALPN、信任链）均返回稳定错误类别，不回显私钥或证书全文。
- 上下文取消立即中断阻塞 IO 并释放资源。
- 关闭完成后 goroutine、会话、流与监听器计数归零。

实机：

- **真实网络下的 KCP 弱网表现与 QUIC 公网路径表现需用户在目标环境确认实机通过**：包括跨运营商、高丢包、NAT 空闲回收与移动网络切换场景。本地回环与 CI 测试不能替代真实网络验收。
- 弱网注入测试只能证明相对趋势，不能替代实机结论。

## 6. 风险与待定

- **QUIC 官方互操作已在本机复现通过**：`quic-go` 适配、ALPN `frp`、以及「控制连接与工作连接是同一会话上的两条双向流」的映射均已验证（黑盒登录 + TCP 代理端到端回显，wire v1/v2）。关闭单条流不得关闭会话这一点由显式 `ownsSession` 区分保证。
- **KCP 官方互操作登记为基线限制**：固定基线 frpc v0.70.0 在 `transport.protocol = "kcp"` 下不发出任何数据报（默认、`tls.enable=true`、`tcpMux=true` 三种组合均为零流量；对照官方 frps v0.70.0 trace 日志同样收不到连接），且 `frpc verify` 判定配置合法、v0.70.0 声明支持 `kcp`。经用户确认按基线客户端限制登记，不计入 P1 互操作门禁；JRP 侧 KCP 由引擎级端到端用例（控制会话建立、通配监听 + IPv4 拨号）与适配单测覆盖。
- **真实网络已完成**：弱网（链路夹具注入延迟/丢包/抖动）、公网 NAT（2026-09-27 公网实机批次，QUIC 控制入口 × wire v1/v2 通过）、跨平台（Linux 服务端 ↔ Windows 客户端）与连接迁移（传输层观测，见 §4）均已完成。
- **类型隔离是最大技术风险**：QUIC 的多流与连接迁移语义天然与「一个句柄一条连接」的抽象不完全吻合。若评审判定无法在维持抽象的前提下隔离类型，必须先新增 ADR 说明取舍，不得在公共接口上开后门类型。
- **UDP 端口暴露增加攻击面**：KCP 与 QUIC 都在 UDP 上监听，需防止伪造源导致的会话膨胀。会话上限、速率约束与来源校验策略需要在实现前定量化。
- **P1 不启用 0-RTT**：0-RTT 的重放风险与会话层重放边界存在交互，本轮明确排除；若未来需要，须另立 ADR。
- **参数调优依赖真实网络**：窗口、重传与空闲超时的合理取值只能在真实网络压测后确定，本规格不预设具体数值。
- **与 FR-05b 的完成顺序**：两种依赖都待批准，建议先完成一种传输再回头校验抽象形状，避免同时调整抽象与两个实现。
