# 功能规格：有界类型化事件订阅与只读状态快照

> 状态：已交付 · 关联 PRD：FR-27 · 分支：feature/core-event-subscription

## 1. 背景与目标

嵌入宿主需要观测 Engine 内部发生了什么：客户端上下线、代理状态变化、配置应用结果、异常等。同时 NFR「数据面隔离」与 `.claude/rules/architecture-invariants.md` §5 要求运行事件必须经有界通道交给适配器，**慢消费者不得无限阻塞数据面**。

本功能解决的问题：

- 直接把内部状态暴露给宿主会形成穿透式耦合（ADR-0003 明确禁止适配器穿透读取或修改 Core 内部状态）。
- 无界缓冲或阻塞式回调会让慢宿主反向拖慢数据转发，把观测通道变成可用性故障源。
- 一旦事件丢失，宿主无法知道自己遗漏了什么，只能靠重启重建视图。

目标：提供**有界、类型化、非阻塞**的事件订阅，配套**只读状态快照**，使宿主既能实时观测，又能在事件溢出后重新同步出一致视图。

使用者：jrps/jrpc 适配器（指标、日志、审计、通知）、第三方嵌入宿主的运维视图。所属阶段：P1。

## 2. 需求

- 事件类型化：每种事件有固定类型标识与固定字段结构，宿主用类型断言或类型开关处理，不做字符串解析。
- 订阅缓冲有界：缓冲规模由 Core 常量或订阅参数确定，超出即触发明确降级，绝不无限增长。
- 慢消费者不得阻塞数据面：事件投递不阻塞转发路径、不阻塞 Apply、不阻塞 Shutdown。
- 溢出可被宿主检测：溢出后发布重同步事件，宿主据此调用状态快照重建视图。
- 状态快照只读：返回深复制值，宿主修改不影响 Core 内部。
- 事件内容脱敏：不携带 token、密码、Cookie、Authorization 或完整正文。
- 多订阅者相互隔离：一个订阅者溢出或关闭不影响其他订阅者，也不影响 Engine。

- **范围内**：
  - 订阅的创建、读取与关闭（`Subscribe`、`Events`、`Close`）。
  - 事件信封与首版事件类型集合：客户端连接/断开、代理状态变化、Apply 结果、Engine 停止、重同步要求。
  - 有界缓冲与按事件等级的溢出降级策略。
  - 只读状态快照：Engine 状态、active 与 last-good revision、客户端摘要、代理摘要、连接计数。
  - 可选 `*slog.Logger` 注入（日志是可选诊断手段，不是业务契约）。
- **范围外**：
  - 不做 SSE/HTTP 推送、WebSocket 广播或管理 API 的 `/api/v1` 事件端点；对外推送属于 jrps 适配器。
  - 不做事件持久化、重放、离线补发或跨进程事件总线。
  - 不做指标聚合、告警判定、审计落库、通知触发；这些由适配器消费事件后自行实现（ADR-0003、ADR-0004）。
  - 不做订阅过滤表达式引擎；首版只提供按事件等级与按类别的订阅选项，过滤器函数属于后续增强。
  - 不做事件采样率、限速或统计聚合配置。
  - 不涉及 P3 的多节点事件汇聚、分布式追踪或集中式可观测后端（ADR-0009）。

## 3. 设计

### 3.1 包布局与依赖方向

- 事件类型与订阅接口位于根包 `github.com/wcpe/jrp/core`；Engine 侧的 `Subscribe` 方法在 `core/server` 与 `core/client` 上转发。按 ADR-0012，P1 只有 `core`、`core/server`、`core/client` 三个公共导入路径，事件能力并入根包而不新增第四个包。
- 状态快照类型位于各自 Engine 包（服务端与客户端快照内容不同），只读语义与深复制规则共用同一套约定。
- 依赖方向：`core/server`、`core/client` → `core` → 标准库；根包不导入 Engine 包，也不导入 `core/internal`。
- 公共签名只出现标准库类型与 Core 自有值类型；不泄漏 Gin、GORM、SQLite、quic-go、kcp-go 或 `internal` 类型（ADR-0002 边界约束，不重复正文）。
- 事件不得携带可变内部指针、`net.Conn`、`net.Listener` 或任何活对象引用；只携带值、标识与计数。

### 3.2 API 形态

```go
sub := eng.Subscribe(event.Options{Capacity: 128})
defer sub.Close()

for ev := range sub.Events() {
    switch e := ev.(type) {
    case event.ClientConnected:
        // 使用 e.ClientID、e.RemoteAddr
    case event.ApplyResult:
        // 使用 e.Revision、e.Stage、e.Error
    case event.ResyncRequired:
        // 重建视图：state := eng.State()
    }
}
```

- `Subscribe(opts) *Subscription`：创建订阅并立即开始接收此后产生的事件；不回放历史。
- `Events() <-chan Event`：只读接收通道；宿主负责消费。
- `Close()`：停止接收并释放缓冲；幂等，可重复调用；关闭后 `Events()` 通道被关闭且不再写入。
- `State()`：返回当前只读状态快照的深复制值，任何时刻可调用，与订阅无关。
- `Options.Capacity` 为 0 时使用 Core 默认常量；超过 Core 上限时收敛到上限，不返回错误（避免让观测开关成为启动失败原因）。

### 3.3 事件模型

事件信封与类型化载荷：

```go
type Event interface {
    Type() Type     // 稳定类型标识
    Level() Level   // 等级：关键、常规、诊断
    At() time.Time
}
```

- 每个具体事件是独立结构体（如 `event.ClientConnected`、`event.ProxyStatusChanged`、`event.ApplyResult`、`event.EngineStopped`、`event.ResyncRequired`），字段全部为值类型。
- `Type` 使用具名常量枚举，宿主不得依赖其底层数值或字符串。
- 首版事件集合（只服务于已交付能力）：
  - 客户端连接成功与断开（含客户端标识、远端地址摘要）。
  - 代理状态变化（名称、类型、新状态）。
  - Apply 结果（revision、阶段、是否成功、安全可公开的错误摘要）。
  - Engine 停止（最终错误）。
  - 重同步要求（溢出时发布，携带丢弃计数与原因）。
- 事件字段脱敏：客户端标识与代理名可以出现；token、密码、Cookie、Authorization 与正文一律不出现。地址信息只到地址摘要层级，不携带可反推凭证的字段。

### 3.4 缓冲、溢出与降级

- 每个订阅拥有**独立有界缓冲**；缓冲满时按事件等级降级：
  - 诊断级：直接丢弃，不计数告警。
  - 常规级：丢弃并累计丢弃计数。
  - 关键级：优先保留——丢弃一个最旧的常规级事件腾出空间；若缓冲里全是关键级事件，则丢弃最旧的关键级事件。
- 任何情况下投递都**不阻塞数据面**：投递采用非阻塞发送，失败即走降级路径，不等待、不重试、不回调宿主。
- 溢出后向该订阅发布一条 `ResyncRequired`，携带本次丢弃计数；宿主收到后调用 `State()` 重建视图。
- 溢出计数与 `ResyncRequired` 本身也需占用缓冲，因此 Core 为每条订阅预留保留位，保证重同步事件总能入队。
- 溢出后若宿主仍未消费，不反复发布重同步事件：同一连续溢出窗口内只发布一次，直到宿主消费或再次发生新的溢出。

### 3.5 只读状态快照

- `State()` 返回深复制值：切片、映射与嵌套结构全部复制，宿主修改返回值不影响 Core；Core 内部后续变化也不影响宿主已取到的值。
- 快照内容包括：Engine 运行状态、active revision、last-good revision、客户端摘要列表（标识、连接状态、代理数）、代理摘要列表（名称、类型、状态）、活动连接计数、订阅丢弃计数。
- 快照是**某一时刻的一致性视图**：Core 在生成快照期间不得返回半更新状态；生成过程在锁内完成但不执行网络 IO。
- 快照不替代事件流：它只回答「现在是什么状态」，不回答「发生过什么」；历史与审计由适配器自行记录。
- 快照与 FR-26 的 revision 语义一致：`active` 是当前生效版本，`last-good` 是最近成功版本；快照中不得出现「desired」字段，因为 Core 不知道也不持久化 desired（ADR-0004）。
- `last-good` 字段的存在依据为 ADR-0012：Core 持有运行态 last-good 用于回滚决策，因此它出现在只读状态快照中；外壳另存 Apply 结果记录用于审计，两者目的不同、不构成双真源。

### 3.6 生命周期与并发

- Engine Shutdown 时按序：停止产生新事件 → 向所有订阅发布 `EngineStopped` → 关闭所有订阅通道 → 释放缓冲。
- Shutdown 不等待慢消费者；慢消费者不会延长 Engine 停止时间。
- 订阅可在 Engine 运行期间任意创建与关闭；关闭后该订阅不再收到事件，其他订阅不受影响。
- 并发调用 `Subscribe`、`Close`、`State` 均安全；`go test -race` 覆盖多订阅者并发关闭场景。
- 未注入 logger 时不向标准输出直写；注入 logger 后日志使用中文并脱敏。

## 5. 验收标准

正常路径：

- 订阅创建后能按序收到客户端连接、代理状态变化与 Apply 结果事件；事件类型断言成功，字段值与预期一致。
- 正常消费速度下不出现丢弃，`State()` 返回的 active revision 与 FR-26 中 Apply 的结果一致。
- 关闭订阅后通道被关闭，不再收到事件；重复 `Close` 安全。
- Engine 正常 Shutdown 时订阅收到 `EngineStopped`，随后通道关闭。

边界：

- 缓冲规模设为 1 且事件连续产生时不发生阻塞、不 panic，溢出路径被触发。
- `Options.Capacity` 为 0 时使用默认常量；超过 Core 上限时收敛到上限且订阅仍然可用。
- 多订阅者中只有一个慢消费者时，其他订阅者不受影响，仍收到完整事件。
- 快照中的客户端与代理摘要在并发 Apply 期间读取，不返回半更新状态；读取到的 revision 要么是切换前值要么是切换后值。
- 未注入 logger 时不向标准输出直写任何内容。

错误路径：

- 慢消费者长时间不读：数据面吞吐不下降（与无订阅时的基准相比在既定容差内（容差数值由 FR-14 压测定稿后补齐，补齐前不作为门禁）），Apply 与 Shutdown 不被延迟。
- 缓冲溢出：收到 `ResyncRequired`，其丢弃计数大于 0；宿主随后调用 `State()` 得到的视图与 Core 实际状态一致，可据此重建。
- 连续溢出窗口内 `ResyncRequired` 只发布一次；宿主消费并再次溢出后才会再次收到。
- 关键级事件优先：缓冲被诊断级与常规级填满时，关键级事件仍能被保留并送达。
- Engine 因异常停止：订阅收到带最终错误的 `EngineStopped`，错误内容不含 token、密码、Authorization 或正文原文。
- 订阅已关闭后再有事件产生：不向已关闭通道写入，不发生 panic。

资源与并发：

- 多订阅者并发创建与关闭、Engine 并发 Shutdown 场景下 `go test -race ./...` 通过。
- 全部订阅关闭与 Engine Shutdown 后无残留 goroutine 与缓冲泄漏。
- 快照返回值被宿主修改后，再次调用 `State()` 仍返回 Core 的真实值（深复制生效），且快照内部切片与映射无别名共享。
- Windows、Linux、macOS 三平台 `task test:core` 与 `task lint:go` 通过。

## 6. 风险与待定

- **吞吐容差需量化**：「慢订阅者不降低吞吐」需要一条可比对的基准与明确容差。具体数值应在实现时结合 NFR「性能门禁」在同机同场景测定，并写入本规格的验收条目。
- **默认缓冲规模需量化**：默认容量与上限目前只确定「Core 常量、宿主可调但收敛」的原则，具体数值应在实现时定标并记录。
- **事件等级划分依据**：诊断、常规、关键三级的归属需要在实现时对每个事件类型明确判定；判定标准应写入长期文档，避免后续事件随意标为关键级而挤掉降级空间。
- **快照在超大部署下的成本**：NFR 规模基线为 200 客户端与 2000 代理，深复制整份快照的开销需要实测。若开销不可接受，需评估按类别分页读取的替代方案，但那会扩大公共面，应作为独立决策。
- **与 SSE 管理事件的映射关系**：jrps 的管理 REST 与 SSE 端点由适配器定义。适配器如何把 Core 事件映射为 `/api/v1` 的 SSE 事件、以及在 `ResyncRequired` 时如何刷新浏览器视图，属于外壳设计，不在本功能范围，但需在集成时验证不会反向把 SSE 的背压传回 Core。
