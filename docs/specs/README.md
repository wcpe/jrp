# 功能规格（specs）

命中规格检查项的功能在开发前创建一份工作规格：一个功能一个文件 `docs/specs/功能名.md`，集中记录需求、设计、任务与验收。模板见 [`_template.md`](_template.md)。

## 何时创建

新增或增强类需求命中以下任一项时必须创建：

1. 引入新数据模型、表或 Schema。
2. 引入新外部接口，包括 API、命令、事件或配置项。
3. 跨越两个及以上模块。
4. 需要新增 ADR 或取代已有 ADR。
5. 存在下游需求依赖。
6. 涉及并发、事务、锁或状态机。

全部不命中时可免建。小改动、缺陷修复、纯重构和依赖升级通常不建 spec，但仍须遵守测试和文档同步要求。

## 与长期文档的分工

- `docs/PRD.md`：长期需求路线图，每个功能是一行 FR 与状态。
- `docs/specs/功能名.md`：功能开发期的详细工作规格。
- `docs/ARCHITECTURE.md`：系统当前实现方式。
- `docs/PROTOCOL.md`：Core 兼容协议当前契约。
- `docs/adr/*`：重大决策及其原因。

功能交付后，将长期事实归并到 PRD、ARCHITECTURE、PROTOCOL、API、OPERATIONS、SECURITY 和 CHANGELOG；spec 作为历史工作规格保留，避免继续成为第二真源。

## 使用方法

1. 复制 `_template.md` 并使用英文 kebab-case 文件名。
2. 填写关联 FR、范围、设计、任务、测试与实机验收。
3. 实现期间持续更新任务状态，但不得用任务勾选替代验证证据。
4. 交付后更新长期文档与 PRD 状态。
