# 功能规格：TCP 连接传输

> 状态：草拟 · 关联 PRD：FR-05a · 分支：feature/transport-tcp

## 1. 背景与目标

FR-05a 要求 Core 支持 TCP 连接传输，并且**不引入任何第三方依赖**。TCP 是官方 frpc 与 jrpc 的默认传输方式，也是所有其他传输进行对照的基线：任何更高层的能力（wire 编解码、控制会话、工作连接、代理转发）都必须先在 TCP 上跑通，才能在其他传输上验证。

本规格解决的具体问题是：把「一条 TCP 连接」抽象成 Core 可组合的字节流资源，同时把建链、复用、生命周期与异常关闭的语义钉死，避免这些决策散落在会话层或代理层里导致行为不一致。使用者：Core 的传输接入层、控制会话、工作连接路径，以及嵌入 Core 的宿主应用。所属阶段：P1。

## 2. 需求

- 提供基于 Go 标准库 `net` 的 TCP 监听与拨号能力，**零第三方依赖**。
- 控制连接与工作连接共用同一套传输抽象，差异只在建链用途与生命周期归属。
- 支持工作连接池的复用与上限约束。
- 生命周期必须可判定：启动成功后接管资源；关闭后无残留监听器、连接或 goroutine。
- 异常关闭（对端重置、半关闭、超时、取消）必须释放资源并产生可观测事件。
- 所有阻塞 IO 不得在持有全局锁时执行。
- 传输公共接口只暴露标准库类型与 Core 自有值类型，不泄漏任何第三方实现类型。

- 范围内：TCP 监听、拨号、连接封装、读写超时、优雅关闭与强制关闭、半关闭处理、工作连接池复用与上限、异常路径资源回收。
- 范围外：
  - **「JRP 客户端连接官方 frps」这一反向兼容方向，本轮不做**；TCP 传输规格本身不承载任何兼容方向承诺。
  - WebSocket / WSS 传输（FR-05b）、KCP / QUIC 传输（FR-05c）。
  - TLS 终止、证书治理与 HTTPS 正文采集（FR-21，P2）。
  - wire 编解码与会话层语义（FR-04、FR-03）。
  - P3 的数据节点、节点 RPC、选举、分布式锁、共享数据库、租户、RBAC、OIDC。

## 3. 设计

### 3.1 零第三方依赖

FR-05a 只允许使用 Go 标准库：`net`、`net/netip`、`context`、`time`、`sync`、`io` 等。**Core 的 `go.mod` 不得因本规格新增任何 require 条目。** 该约束由依赖图门禁自动验证：Core 依赖图穷举不得出现新增第三方模块。

选择纯标准库实现的理由：TCP 是唯一零依赖即可完整交付的传输，先以它建立传输抽象的形状，再用同一形状去评估另两种传输引入依赖的代价。

### 3.2 传输抽象

传输层向上提供统一的能力，不区分底层是 TCP 还是未来其他传输：

- **监听**：接收地址与上下文，返回可被关闭的监听器句柄。
- **拨号**：接收目标地址与超时，返回连接句柄。
- **连接**：实现标准库的读写与关闭语义，附加用途标记（控制连接 / 工作连接）与建链时间。

抽象只暴露标准库接口（`net.Listener`、`net.Conn`、`context.Context`）与 Core 自有值类型（用途、限制参数），满足「Core 公共接口不泄漏第三方实现类型」的 NFR。

### 3.3 监听与生命周期

- 监听资源由宿主注入或由配置快照声明；Core 在 prepare 阶段创建，publish 后成为活跃资源。
- 启动成功后 Core 接管该监听器；启动失败时资源仍由宿主持有，Core 不得半接管。
- 关闭遵循两阶段：先停止接收新连接，再按排空上限等待已有连接自然结束；超过上限强制关闭。
- 关闭完成后必须可断言：无残留监听器、无残留连接、无残留 goroutine。

### 3.4 连接建立与读写超时

- 拨号必须带超时，禁止无超时拨号。
- 连接建立后设置读写截止时间的策略由上层按消息类型驱动；传输层只提供设置入口，不硬编码业务超时。
- 所有超时值来自配置快照，不在代码中写死。

### 3.5 复用与工作连接池

- 工作连接按「每个控制会话一个池」组织，池有明确上限。
- 池内连接按用途复用：控制连接不参与数据转发，工作连接只服务绑定的代理。
- 达到上限时新请求被推迟或拒绝，必须产生可观测事件，不得无限等待。
- 空闲连接在空闲上限后被回收，回收时释放缓冲与 goroutine。

### 3.6 异常关闭处理

| 异常类别 | 处理 |
|---|---|
| 对端重置连接 | 标记连接失效，关闭并释放资源，产生连接关闭事件 |
| 对端半关闭（只关写方向） | 按上层语义决定是否继续读完剩余数据；不得无限等待 |
| 读写超时 | 取消该次 IO，按上层策略关闭连接或重试 |
| 上下文取消 | 立即中断阻塞 IO，释放连接与 goroutine |
| 监听 Accept 失败 | 区分临时错误与致命错误：临时错误退避后继续，致命错误停止监听并上报 |
| 拨号失败 | 返回错误，不重试到底；重试策略由上层控制 |

所有异常路径都必须保证：goroutine、连接、缓冲区与临时状态被回收（`docs/PROTOCOL.md` §11）。

### 3.7 与 ADR 的关系

- Core 模块边界、禁止依赖方向与「Core 只承载数据面能力」遵循 ADR-0002 与 ADR-0003。
- 无中断配置应用（prepare、health-check、atomic publish、drain）对监听器的接管与释放语义遵循 ADR-0005。
- 兼容实现的独立性与固定基线遵循 ADR-0010（取代 ADR-0001），本规格不重复其决策正文。

## 5. 验收标准

正常路径：

- 本地回环上完成监听、拨号、双向读写与优雅关闭。
- 控制连接与工作连接可并存于同一监听器，用途标记正确分离。
- 工作连接池在未达上限时复用连接，达到上限后按策略推迟或拒绝。
- 关闭流程停止接收新连接，已有连接在排空上限内保持连续。

零依赖边界：

- Core 的 `go.mod` 在本规格交付前后无新增第三方 require；依赖图门禁通过。
- 传输公共接口签名中只出现标准库类型与 Core 自有值类型。

边界：

- 拨号在不可达地址上按超时返回错误，不悬挂。
- 零长度写入、单次大块写入、连续小包写入均正确收发。
- 排空上限到达后强制关闭，不无限等待。
- 池上限与空闲上限的边界值（等于上限、上限加一）行为可判定。

错误路径：

- 对端重置、半关闭、读写超时、上下文取消四类异常均释放资源，无 goroutine 泄漏。
- 监听 Accept 遇到致命错误时停止监听并上报，不静默退出循环。
- 启动失败时监听器未被 Core 接管，宿主仍可关闭或复用。

生命周期与实机：

- 关闭完成后通过 goroutine 计数与连接计数断言无残留。
- 并发建立与关闭大量连接时无竞态（竞态检测通过）。
- 真实网络下的长连接稳定性、大流量吞吐与连接泄漏行为需用户在目标网络环境确认实机通过；本地回环测试不能替代真实网络验收。

## 6. 风险与待定

- **真实网络行为无法由回环覆盖**：NAT 空闲回收、中间设备断链、长肥管道下的窗口行为都只在真实网络中出现，需用户实机确认。
- **超时默认值需要压测校准**：本规格不锁定具体数值，超时与池上限由配置快照提供；默认值需结合规模基线（200 客户端 / 2000 代理）压测后确定。
- **半关闭语义依赖上层**：传输层无法独立决定半关闭后是否继续读，需要与工作连接和代理层协同确认，避免两处各写一套。
- **传输抽象形状需被另两种传输验证**：本轮只有 TCP 一个实现，抽象是否过度或不足要在 FR-05b / FR-05c 落地时回头校验，届时应以最小改动适配而非大改抽象。
