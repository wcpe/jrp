# 功能规格：Windows SCM 服务

> 状态：草拟 · 关联 PRD：FR-31 · 分支：feature/windows-scm-service

## 1. 背景与目标

部署在 Windows 上的 `jrps` 与 `jrpc` 需要在无人登录会话时自动启动，并在进程崩溃后自动恢复。若每次开机都要有人远程进去手工运行，代理网络就会长期处于不可用状态；若用计划任务或自启动目录替代，就丢失了失败恢复、明确的停止控制和可判定的运行状态。

FR-31 要解决的问题是：让 `jrps` 与 `jrpc` 注册为 Windows SCM（服务控制管理器）服务，且注册结果满足固定语义——默认 LocalService 账户、Automatic 启动类型、失败恢复动作带有限退避、正确处理 Stop 与 Shutdown 控制码、30 秒停止期限、优雅停止、服务注册与命令行不含任何凭据、卸载不删数据。

本规格是 FR-29 的平台落地之一：服务抽象与 CLI 契约由 `platform/service` module 规格定义，本规格只定义 Windows 侧的具体形态。使用者是部署者与管理 JRP 的工程师。所属阶段 P1（切片 S5）。Core 边界遵循 ADR-0002 与 ADR-0003，命令真源遵循 ADR-0008，本规格不重复其决策正文。

## 2. 需求

- 支持将 `jrps` 与 `jrpc` 注册为 Windows SCM 服务。
- 默认使用 **LocalService** 账户运行；不使用 LocalSystem，不要求以管理员身份运行服务进程；不接受在注册时传入账户密码或其他凭据。
- **Automatic 启动类型**：主机启动后无人登录也能自动运行。
- **失败恢复动作**：服务异常终止后由 SCM 按配置的失败动作自动重启；重启延迟按有限退避递增，失败计数在规定窗口后重置。
- 正确处理 **SERVICE_CONTROL_STOP** 与 **SERVICE_CONTROL_SHUTDOWN** 控制码：收到后启动优雅停止流程。
- **停止期限 30 秒**：停止请求给进程 30 秒优雅退出时间，超时才接受被终止。
- **优雅停止**：进程在该期限内自行收尾（停止接收新连接、按既有生命周期关闭），不靠强制结束完成正常流程。
- 服务注册内容与**进程命令行不得包含 token、密码或通知凭据**。
- 数据保留：uninstall 不删除 SQLite、日志、证书或正文数据；默认数据目录 `%ProgramData%\JRP\jrps` 与 `%ProgramData%\JRP\jrpc`，允许绝对路径覆盖。
- 服务名固定，单机每个二进制只允许一个实例。
- 六个子命令（install、uninstall、start、stop、restart、status）与 FR-29 一致。
- 及时向 SCM 报告状态：启动中、运行中、停止中、已停止四种状态必须如实上报，不得长驻"启动中"掩盖真实状态，也不得在仍在处理请求时报"已停止"。
- 数据目录不存在时创建并配置访问控制；已存在时不删除或改写既有内容。
- 非 Windows 平台执行这些子命令返回明确中文错误，不静默降级。

- 范围内：
  - Windows SCM 服务的创建、配置、删除，以及失败恢复动作的配置。
  - LocalService 账户与 Automatic 启动类型作为默认形态。
  - Stop 与 Shutdown 控制码的处理与 30 秒停止期限。
  - install、uninstall、start、stop、restart、status 在 Windows 上的实现。
  - 服务状态向 SCM 的如实上报与服务退出码语义。
  - 卸载保留数据：保留 SQLite、正文、证书、运行日志与审计输出。
  - 与 `platform/service` module 的对接方式。
- 范围外：
  - **Windows 用户会话服务**、登录触发任务、任务计划程序触发器与启动目录快捷方式。
  - 计划任务（Task Scheduler）作为自启动载体；本功能的自启动只走 SCM。
  - 自动生成或管理 Windows 服务账户、托管服务账户、域账户与密码凭据。
  - 除 LocalService 以外的其他内置或自定义账户及其凭据管理。
  - macOS 与 Linux 的自启动形态（Linux 见 FR-30）。
  - 交互式服务、桌面 UI、通知区域图标与服务托盘。
  - Windows 事件日志的集中转发、自定义事件源 schema 与日志订阅编排。
  - 组策略分发、MSI/EXE 安装包、 Chocolatey/Scoop/winget 打包与分发。
  - 服务自愈之外的业务健康探测、自动升级与看门狗；第三方守护工具（如 NSSM 之类的包装器）。
  - P3 的数据节点、节点 RPC、选举、分布式锁、共享数据库、HA、多管理员、RBAC、OIDC。

## 3. 设计

### 3.1 与 platform/service 的关系

Windows 实现位于 `platform/service` module 内，由构建约束隔离，只编译到 Windows。它实现 FR-29 定义的动作：探测、安装、卸载、启停、状态查询。上层 `apps/jrps` 与 `apps/jrpc` 只传入引导参数（可执行文件路径、数据目录、监听地址），不感知 SCM API 细节。

依赖方向不变：`platform/service` 不导入 `core` 与 `apps/*`；`core` 不依赖该 module。

### 3.2 服务注册形态

install 创建一个 SCM 服务，关键属性：

| 属性 | 取值 | 理由 |
|---|---|---|
| 服务名 | 固定名，随 jrps/jrpc 不同 | 单机单实例、可寻址 |
| 显示名 | 中文显示名，标明是 jrps 还是 jrpc | 便于运维识别 |
| 启动类型 | Automatic | 开机无人登录自动运行 |
| 服务账户 | LocalService | 最小权限 NFR，且无需携带凭据 |
| 二进制路径 | 可执行文件绝对路径 + 引导参数 | 不含任何凭据 |
| 失败恢复（第一次失败） | 重启服务 | 异常终止后自动恢复 |
| 失败恢复（第二次失败） | 重启服务，延迟更长 | 有限退避 |
| 失败恢复（后续失败） | 按配置的最终动作执行 | 避免无限即时重启 |
| 失败计数重置间隔 | 明确的秒数 | 窗口后恢复正常计数 |
| 重启延迟 | 明确的秒数 | 退避起点 |

**凭据禁令**：注册时不得以任何形式写入账户名/口令对；LocalService 是内置账户，无需口令。服务二进制路径只携带可执行文件绝对路径、`--data-dir`（数据目录）与必要的监听地址引导参数，**不得**携带 token、管理员密码、Webhook secret、SMTP 密码或任何通知凭据。测试对注册出的二进制路径做字符串断言：不得出现类口令字段与类 token 值。

### 3.3 控制码处理与优雅停止

- 服务进程实现 SCM 控制处理器，至少处理停止与关机两类控制码，以及其他控制码的安全默认处理。
- 收到停止或关机控制码后：立即向 SCM 上报"停止中"，然后在 30 秒内自行收尾；期限内完成则上报"已停止"并以成功退出码退出；超期也须上报终态，不得悬停在"停止中"。
- 收尾期间进程按自身生命周期处理：停止接收新连接、按既有排空语义处理已有连接、释放监听与资源。
- **Shutdown 与 Stop 走同一条优雅停止路径**：系统关机不得被当作异常终止，因此不得以非正常退出码退出，否则会被失败恢复动作判定为失败并在下次开机前无谓重试。
- 停止期间禁止向 SCM 谎报"已停止"：只有在资源实际释放完成后才切换到终态。

### 3.4 失败恢复与自动重启边界

- 只有进程以失败退出码退出或被系统判定为崩溃时才触发失败恢复动作；正常停止与系统关机不触发。
- 失败恢复动作由 SCM 原生机制执行，进程内部不写自己的重启循环。
- 退避是有限的：多次失败后的延迟递增且存在最终动作，不得无限即时重启。
- 进程退出码语义明确：成功、失败与"请求重启"的语义不得混用；不得用"故意失败退出"换取 SCM 重启，也不得用"伪装成功退出"掩盖崩溃。

### 3.5 数据目录与访问控制

- 默认数据目录 `%ProgramData%\JRP\jrps`（jrps）与 `%ProgramData%\JRP\jrpc`（jrpc），允许绝对路径覆盖。
- install 在数据目录不存在时创建，并授予 LocalService 对该目录的读写权限；目录已存在时保留既有内容与访问控制，只确保服务账户可读写。
- LocalService 的既有权限边界决定了哪些位置可写：若指定的绝对路径不在服务账户可写范围内，install 必须失败并给出明确中文错误，不得静默降权到不可写位置。
- 卸载只删除服务注册本身，**不删除数据目录中的任何文件**。

### 3.6 安装与卸载流程

安装：

1. 校验具备创建 SCM 服务的权限。
2. 校验或创建数据目录并配置访问控制。
3. 以 LocalService 与 Automatic 启动类型创建服务；二进制路径不含凭据。
4. 配置失败恢复动作、退避延迟与失败计数重置窗口。
5. 不自动启动：安装后状态为"已安装已停止"，由管理员显式 `start`。

卸载：

1. 若服务存在则按 stop 流程停止（30 秒期限），等待进入已停止态。
2. 删除 SCM 服务。
3. **不删除数据目录及其中的任何文件**，并在输出中提示数据已保留及其路径。

创建失败时不残留半个注册：失败后应删除可能已创建的服务对象，使同一服务可再次 install。

### 3.7 状态查询

`status` 读取 SCM 服务状态并映射到 FR-29 的统一退出码：未安装、运行中、已停止、以及中间态（启动中/停止中）。中间态必须可判定，不得与"运行中"或"已停止"混淆；必要时以等待加超时的方式确认收敛，超时后如实报告当前状态而非猜测。

## 5. 验收标准

自动化（可在具备相应权限的 Windows 环境中验证）：

- 服务以固定服务名注册成功；重复 install 不产生第二个服务。
- 注册属性断言通过：启动类型为 Automatic；服务账户为 LocalService；二进制路径为可执行文件绝对路径且不含凭据。
- 失败恢复断言通过：配置了失败后的重启动作、递增的重试延迟、有限次数的最终动作，以及失败计数重置间隔。
- 凭据断言通过：二进制路径与服务配置中不含类口令、类 token 或通知秘密字段；尝试通过 install 传入这类参数时返回明确中文错误而非写入服务配置。
- 数据目录：缺省值正确（jrps 为 `%ProgramData%\JRP\jrps`，jrpc 为 `%ProgramData%\JRP\jrpc`）；传入绝对路径时使用该路径；服务账户可读写；指向不可写位置时 install 失败并给出明确中文错误。
- 卸载保留数据：uninstall 前生成 SQLite 主文件、日志文件与一个正文分段文件；uninstall 后这些文件与数据目录均存在且内容可读，输出中提示数据保留路径。
- 停止语义：收到停止控制码后上报"停止中"，在 30 秒内上报"已停止"并以成功退出码退出；状态机不悬停在中间态。
- 关机语义：收到关机控制码走同一优雅停止路径，以成功退出码退出，不触发失败恢复。
- 幂等：连续两次 install 成功且只有一个服务；连续两次 uninstall 成功；start 已运行与 stop 已停止不判为失败。
- status 的未安装、运行中、已停止与中间态有确定退出码与中文输出。
- 安装失败后无残留服务注册，再次 install 可成功。
- 该 module 在 Windows 上的测试通过；`go vet`、依赖门检查通过；Linux 与 macOS 上 Windows 侧代码不参与编译。

**真实 Windows 主机重启验收（需真实主机，需用户确认）**：

> 以下各项不能在容器或虚拟化的替代机制中确认：必须由用户在真实 Windows 主机上执行并确认结果。

1. 在真实 Windows 主机上以管理员权限为 `jrps` 执行 install；确认服务已创建、启动类型为 Automatic、登录账户为 LocalService。
2. 执行 `start`，确认服务进入运行中；以任务管理器或进程属主确认进程以 LocalService 运行，而非管理员或 LocalSystem。
3. 为 `jrpc` 重复步骤 1 与 2，确认两个服务可并存且各自只有一个实例。
4. **执行真实主机重启**：重启后不登录任何用户会话，由用户确认两个服务均自动运行，代理能力可用。
5. 确认重启后数据目录内容与重启前一致，且 SQLite 可正常读写。
6. 执行 `stop`，确认在 30 秒内完成优雅停止；由用户确认停止后等待若干分钟服务未被自动拉起。
7. 模拟异常终止（结束服务进程树），由用户确认 SCM 按失败恢复动作在退避延迟后自动恢复服务运行。
8. 执行 `restart`，确认中间态可判定且最终为运行中。
9. 执行系统关机再开机，确认服务以 Automatic 自动启动，且上一轮关机未被失败恢复动作判定为异常。
10. 执行 `uninstall`，确认服务被移除，且 SQLite、日志、证书与正文数据目录内容保持不变。
11. 用户确认上述全部步骤通过后，FR-31 才可进入交付判定。

## 6. 风险与待定

- **风险**：LocalService 对某些目录无写权限，管理员可能改用 LocalSystem 绕过，破坏最小权限。缓解方式是 install 在不可写位置直接失败并说明原因，而不是静默换账户。
- **风险**：停止期间上报状态不及时会被 SCM 判定为无响应。缓解方式是收到控制码先上报"停止中"再收尾，并严格遵守 30 秒期限。
- **风险**：30 秒对长连接排空偏紧，运维会用强制结束绕开优雅停止。缓解方式是让进程在该期限内自行决定收尾节奏，并在文档中说明超时后果。
- **风险**：把关机误实现为异常退出，会被失败恢复动作反复重试。缓解方式是 Shutdown 与 Stop 共用优雅停止路径并以成功退出码退出。
- **风险**：服务被运维在"服务"管理单元里手工改属性，与 install 的期望漂移。缓解方式是 status 报告实际 SCM 状态，重新 install 前提示差异。
- **待定**：失败动作的第三次及之后的最终动作选择（不采取行动还是需要人工介入）。当前只约束"有限退避、存在最终动作"，具体形式需与运维取舍后定稿。
- **待定**：具体的重试延迟秒数与失败计数重置窗口取值。需在真实负载下观察崩溃恢复时间后定稿，当前绝不写死在未验证的数值上。
- **待定**：数据目录访问控制的具体授予方式（继承还是显式项）。需与最小权限要求共同确认，目标是仅服务账户与管理员可读写。
