# ADR-0005：采用无中断配置热更状态机

## 状态

已接受

## 背景

代理配置修改若通过进程重启或先关闭旧监听再创建新监听，会切断已有连接并放大配置错误。JRP 需要让大多数配置更新对活动流透明，同时保留清晰的失败与回滚语义。

## 决策

非引导配置统一按 `prepare → health-check → atomic publish → drain` 应用：先准备并验证新资源，再原子发布不可变 active snapshot，最后排空旧资源。发布前失败保留旧 active 与 last-good revision。

## 理由

- 双资源准备把配置错误隔离在 active 路径之外。
- 原子快照让新连接只观察到完整新版本。
- 排空允许活动连接自然结束，满足零中断目标。
- 明确状态机便于测试竞态、回滚和资源释放。

## 后果

- 监听器、路由、会话和依赖资源必须支持准备态与活动态生命周期。
- publish 之前不得关闭旧资源；drain 期间旧资源不得接收新连接。
- 准备失败必须释放新资源并记录 apply result。
- 数据目录、SQLite 路径和管理 API 根监听是三项引导例外，变更需要重启。
- 不允许用自动重启冒充热更。
- 回滚通过创建新的 desired revision 再走同一状态机，不篡改历史版本。

## 备选方案

- **修改后重启进程**：简单但切断连接，不满足产品目标，拒绝。
- **原地修改共享可变配置**：容易产生半更新和竞态，拒绝。
- **先停旧资源再启动新资源**：存在明显中断窗口，拒绝。
