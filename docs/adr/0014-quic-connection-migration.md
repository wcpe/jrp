# ADR-0014：QUIC 连接迁移在传输包内消化，不放宽类型隔离

## 状态

已接受

## 背景

FR-05c 规格 §3 要求：QUIC 迁移发生时，传输层更新对端地址摘要并产生可观测事件；上层不得依赖对端地址做身份判定（身份由会话层鉴权决定）。规格 §6 同时把「类型隔离」列为最大技术风险，并要求：若无法在维持「一个句柄一条连接」抽象的前提下隔离类型，必须先新增 ADR 说明取舍，不得在公共接口上开后门类型。

实现前需要判定：迁移语义能否在维持现有传输抽象的前提下落地，还是必须放宽类型隔离。

## 决策

**迁移语义完全在 `internal/transport` 包内消化，不放宽类型隔离，不新增公共类型。**

具体三条：

1. **迁移由 quic-go 内部完成，传输层只轮询观测。** quic-go 的 `Conn` 在路径变化时保持连接 ID 与 TLS 状态不变，`RemoteAddr()` 自动反映新路径；经检索 quic-go v0.54.0 源码确认它**不提供迁移回调 API**（仅有 `preferred_address` 相关注释与「服务端不能主动发起迁移」的限制）。因此传输包在读写路径上比较 `RemoteAddr()` 的前后值，变化即产出事件——不引入轮询 goroutine，不增加后台协程。
2. **事件载荷只含脱敏后的地址摘要，不含第三方类型。** 新增 Core 自有值类型承载「迁移前/后地址摘要 + 发生时刻」，经 Core 事件通道发布。摘要算法与既有脱敏口径一致，不回显完整地址。
3. **身份判定不引入地址维度。** 会话层鉴权在登录时完成并绑定运行 ID；迁移事件只作观测，不参与任何身份决策。地址伪装因此无法被当作合法身份——这一点由既有鉴权链保证，不需要新增机制。

## 理由

- **抽象无需改动。** `transport.Conn` 仍是「一个句柄一条连接」，`RemoteAddr()` 的语义（对端当前地址）在迁移后依然成立，只是值变了。会话层与代理层不感知迁移，符合规格 §3.3「P1 不使用同一会话内的多流复用承载多条独立连接」的既定取舍。
- **类型隔离可以维持。** 迁移是 quic-go 的内部行为，传输包只需读取 `RemoteAddr()` 的返回值并比较，不需要把 `*quic.Conn` 或 `*quic.Stream` 暴露给公共接口。规格 §3.2 的三条规则（接口签名、适配层、审计测试）均不受影响。
- **事件可观测性有现成通道。** Core 已有有界类型化事件订阅（FR-27），迁移事件复用该通道即可，不需要新增宿主契约。
- **不启用 0-RTT 与主动迁移。** 规格 §3.5 明确 P1 不启用 0-RTT，迁移由对端发起、服务端只观测，因此本决策不涉及重放边界与主动迁移策略。

## 后果

- `internal/transport` 增加迁移观测：比较 `RemoteAddr()` 变化并产出事件，不导出任何 quic-go 类型。
- Core 事件模型增加迁移事件类型，载荷为脱敏地址摘要；宿主可订阅但不得据此做身份判定。
- 类型隔离审计测试（规格 §3.2 第 3 条）继续有效，无需放宽。
- 迁移后的连接生命周期仍由既有空闲超时与关闭路径管理，不引入新的回收路径。
- 若未来需要「迁移后重新鉴权」或「主动发起迁移」，必须另立 ADR 重新评估，本决策不构成先例。

## 备选方案

- **放宽类型隔离，让公共接口暴露 quic-go 类型**：违反 NFR 与规格 §3.2，且会把第三方类型扩散到协议模型与会话层，拒绝。
- **在会话层处理迁移**：会话层需要理解传输路径变化，破坏「会话层无感知差异」的抽象，且 TCP/WebSocket 没有对应语义会导致分支膨胀，拒绝。
- **不产生事件，只更新地址**：满足「更新地址摘要」但缺失「可观测事件」，运维无法区分正常迁移与异常路径变化，拒绝。
- **把迁移当作断线重连处理**：会中断在途流，违反零中断语义，且 QUIC 迁移的全部意义就是避免重连，拒绝。
