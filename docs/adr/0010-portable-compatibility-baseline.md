# ADR-0010：采用可移植的独立兼容基线

## 状态

已接受

## 背景

本决策取代 [ADR-0001](0001-independent-frpc-compatibility.md)。ADR-0001 确立了独立实现和固定兼容基线，但把某台开发机器上的参考仓库绝对路径写入了正式文档。该路径既不是协议事实，也不能在其他开发环境、CI 或外部贡献者机器上复现。

JRP 仍需固定可重复的兼容研究基线，同时保持文档、规则和协议契约与具体工作站目录无关。

## 决策

JRP 继续采用独立实现，并以参考源码仓库的 Git 提交 `e1f1d6ab1b591ec9b596f4b1b6a81cd2960c6314` 作为兼容研究基线。

参考源码仓库的检出位置由各开发环境自行提供，不属于项目架构、协议或构建契约。除保留取代关系的历史 ADR 外，本机检出位置不得写入 README、活动文档、项目规则或入库配置。

JRP 只根据公开线上行为、自有协议规格、黄金向量和黑盒互操作证据实现兼容；不复制、改写、链接、导入 frp 源码或 Go package。

## 理由

- Git 提交能够稳定标识研究基线，无需依赖某台机器的目录结构。
- 移除本机路径后，文档可供 Windows、Linux、CI 和外部贡献者共同使用。
- 保留固定提交仍能确保兼容范围和回归结果可重复。
- 独立规格和黑盒测试继续维持版权与实现边界。

## 后果

- Core 依赖图不得出现 `github.com/fatedier/frp`。
- 文档和规则只能记录参考提交与使用约束，不能记录开发者本机的仓库绝对路径。
- 需要参考源码的本地工具必须通过未入库的运行参数或本地环境提供仓库位置。
- 兼容性变更必须同步 `docs/PROTOCOL.md` 与 JRP 自有测试。
- 临时抓包、对比结果和外部二进制只能放入忽略的临时目录，不得入库。

## 备选方案

- **保留本机路径**：无法跨环境复现，并泄漏开发环境细节，拒绝。
- **只记录分支名**：分支可以移动，不能唯一标识兼容基线，拒绝。
- **不记录任何基线**：无法界定兼容范围和回归目标，拒绝。
- **直接依赖参考实现**：破坏 Core 独立性和既定许可边界，拒绝。
