# ADR-0003：分离控制面、数据面、可执行外壳与 Web

## 状态

已接受

## 背景

JRP 同时需要高性能数据转发、数据库驱动配置、Web 管理、通知和自研客户端配置下发。若管理适配器直接操作 Core 内部状态，或把私有管理消息塞进官方协议，数据面会被数据库与 UI 生命周期耦合，官方 frpc 兼容性也会变得不可控。

## 决策

Core 只暴露稳定端口接收不可变配置快照并发布运行事件。jrps/jrpc 外壳负责装配数据库和管理适配器；React Web 只调用 jrps 管理 API。官方 frpc 和 jrpc 使用相同兼容数据协议，jrpc 私有管理能力使用独立 HTTPS/WSS 通道。

## 理由

- 数据面热路径不受数据库、Web 或外部通知延迟影响。
- 官方兼容协议保持纯净，不引入私有消息导致互操作漂移。
- Web 与 Core 可分别测试和演进。
- 控制面通过稳定端口驱动 Core，避免穿透内部状态和形成上帝类。

## 后果

- Core 不读取 SQLite、不发送通知、不处理管理员会话。
- Web 生产资源只嵌入 jrps，不进入 Core 或 jrpc。
- jrpc enrollment、desired state 和回执通过 `/agent/v1`，不得复用控制连接消息。
- 运行事件进入有界适配队列；慢通知或统计不得阻塞转发。
- 管理 API/DTO 的变化不应迫使 Core 协议模型同步变化。

## 备选方案

- **把管理消息扩展进官方协议**：实现表面统一，但破坏兼容边界，拒绝。
- **Web 直接读取 SQLite**：绕过授权、审计和业务约束，拒绝。
- **Core 直接持有数据库与通知客户端**：导致数据面耦合和难以复用，拒绝。
