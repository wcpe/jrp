# ADR-0007：分离 HTTP 采集元数据与正文存储

## 状态

已接受

## 背景

管理员需要按需查看 HTTP 请求用于排障，但正文体积大、可能敏感，若直接存入 SQLite 会放大写竞争和数据库膨胀。HTTPS 透传时 JRP 不掌握明文，不能虚假承诺采集。

## 决策

P1 仅对逐代理开启的明文 HTTP 采集：请求元数据和正文索引写入 SQLite，正文流式压缩写入分段文件。默认保留 30 天，正文总量上限 5 GiB；正文默认关闭且明文静态存储。

## 理由

- 元数据适合事务查询，正文适合顺序写和分段清理。
- 流式压缩避免一次性把大正文加载到内存。
- 双重保留限制控制隐私暴露和磁盘增长。
- 默认关闭符合最小采集原则。

## 后果

- 关闭采集时数据面不得进入 SQLite 请求记录路径。
- 采集使用有界队列、大小、并发和超时限制，不阻塞代理转发。
- SQLite 索引与分段文件必须具备一致性检查、孤儿清理和恢复策略。
- 正文查看、导出和删除必须审计；API 不暴露真实文件路径。
- 凭证和正文不做静态加密，数据目录与备份泄露会直接暴露内容。
- P1 的 HTTPS 透传不采集正文；P2 终止 TLS 需新规格和证书治理。

## 备选方案

- **正文直接存 SQLite BLOB**：增加写放大与锁竞争，拒绝。
- **对象存储**：对 P1 单机部署过重，留待 P3 评估。
- **默认采集全部正文**：隐私和容量风险不可接受，拒绝。
