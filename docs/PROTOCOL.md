# JRP 兼容协议规格

> 本文以 JRP 自有表述定义 Core 的 frpc 兼容契约。它不包含 Web、SQLite、通知或 P3 分布式控制面协议。

## 1. 兼容基线与独立实现

- 参考来源：由开发环境提供的 frp 参考源码仓库；检出位置不属于协议契约。
- 固定基线：Git 提交 `e1f1d6ab1b591ec9b596f4b1b6a81cd2960c6314`。
- 使用方式：只读研究公开线上行为，并以独立规格和黑盒互操作测试确认。
- 禁止事项：复制、改写、链接、导入 frp 源码或 Go package；复用其注释、错误文案、目录结构、内部命名体系、NAT 策略表或测试组织。
- 兼容证据：JRP 自有单元测试、黄金帧、状态机测试和真实官方 frpc 黑盒运行结果；临时捕获与对比产物只放 `.tmp/`。

## 2. 分层

```text
代理语义：TCP / UDP / HTTP / HTTPS / STCP / XTCP
访客与 NAT：访客鉴权、候选地址交换、打洞结果
会话语义：登录、心跳、代理注册、工作连接、关闭
消息编码：兼容消息类型与 JSON 载荷
wire 封装：v1 或 v2
连接传输：TCP / KCP / QUIC / WebSocket / WSS
```

每层只依赖下层抽象。连接传输负责可靠字节流或相应会话承载；wire 负责边界；消息层负责类型与载荷；会话层负责合法时序；代理层负责转发语义。

## 3. wire v1

wire v1 是兼容基线的传统消息封装：每条控制消息由单字节消息类型、8 字节载荷长度与 JSON 载荷组成。

| 字段 | 长度 | 说明 |
|---|---:|---|
| 消息类型 | 1 字节 | 单个 ASCII 字符，取值由消息种类决定 |
| 载荷长度 | 8 字节 | 有符号整数，网络字节序，紧随其后的 JSON 载荷字节数 |
| 载荷 | 变长 | UTF-8 JSON 对象 |

长度字段为有符号值；负值、超过实现上限或载荷短读均判为协议错误。基线默认载荷上限为 10 KiB，该值属于实现上限而非协议常量，JRP 可在自有上限内取更严格的值。

JRP 必须：

- 只接受已支持的消息类型和有效 JSON。
- 对截断类型、截断长度、超限载荷、未知类型和畸形 JSON 返回协议错误并关闭受影响连接。
- 为消息载荷设置明确上限，不能按对端声明无界分配内存。
- 保留 JSON 向后兼容语义：发送端省略默认/空字段，接收端忽略不影响当前语义的未知字段。
- 不把未知字段原样提升成 JRP 管理配置，也不因字段顺序变化而改变行为。

## 4. wire v2

wire v2 在连接开始使用固定版本魔数区分，并进行客户端/服务端 hello 协商。协商至少覆盖传输摘要、TLS/TCP 复用摘要、消息编码能力和加密能力；P1 消息编码为 JSON。

### 4.1 帧格式

wire v2 帧头固定为 8 字节网络字节序：

| 字段 | 长度 | 约束 |
|---|---:|---|
| frame type | 2 字节 | 客户端 hello、服务端 hello、消息帧等已定义类型 |
| flags | 2 字节 | P1 只接受 0，非零值拒绝 |
| payload length | 4 字节 | 不得超过协商/实现上限，基线默认上限为 64 KiB |
| payload | 变长 | 长度必须与头部一致 |

消息帧载荷以 2 字节网络字节序消息类型 ID 开始，后接 JSON 载荷。少于类型 ID 长度、未知消息类型、错误帧类型、超限长度或截断载荷均为协议错误。

### 4.2 协商规则

1. 客户端写入 v2 魔数后发送 client hello。
2. 服务端校验版本和能力，返回 server hello 或安全可公开的失败。
3. 双方只使用共同支持的消息编码与加密算法。
4. 未识别 v2 魔数时按 v1 兼容路径处理，而不是消费已读取字节。
5. 显式要求 v2 但协商失败时必须失败，不得静默降级到 v1。
6. 连接已选择 wire 版本后不得在同一连接中切换。

## 5. 兼容消息族

JRP Core 按语义支持以下消息族，具体字段以独立实现和黑盒契约测试维护：

- 登录请求/响应：客户端版本、平台、身份、鉴权时间材料、运行 ID、客户端 ID、元数据和连接池摘要。
- 新建/关闭代理请求及响应：代理名称、类型、入口、路由、安全、压缩和限速等 P1 已支持字段。
- 工作连接：服务端请求工作连接、客户端建立工作连接、服务端绑定代理与源/目标摘要。
- 心跳：ping/pong、鉴权时间材料和错误状态。
- UDP 数据包：负载与本地/远端地址。
- 访客连接：访客请求、目标代理、鉴权、加密/压缩选择及响应。
- NAT 打洞：访客/客户端候选地址交换、会话标识、探测结果与报告。

P1 不实现 SUDP、TCPMUX、剩余参数与插件；收到明确不支持的 P2 能力时必须返回可判定的不支持错误，而不是部分应用。

## 6. 控制连接时序

### 6.1 登录与鉴权

1. 客户端完成连接传输和 wire 选择。
2. 客户端发送登录消息，包含客户端身份和基于独立 token 的兼容鉴权材料。
3. 服务端校验客户端状态、token、时间窗口、重放边界和 wire 能力。
4. 成功后服务端分配/确认运行 ID，并进入已认证控制会话；失败则返回失败并关闭。
5. 同一客户端的重连与旧会话竞争必须有确定规则，禁止两个会话无约束地同时拥有同一代理集合。

官方 frpc 只参与此兼容登录。jrpc 的 enrollment 和 desired state 下发不经过该消息族。

### 6.2 心跳

- 已认证控制会话按协商/配置周期发送心跳。
- 心跳必须验证会话归属和必要鉴权材料。
- 超过失活阈值后控制会话关闭并进入代理/工作连接清理流程。
- 网络抖动、单次丢失和超时边界由状态机测试覆盖，禁止无限等待或无界重试。

### 6.3 代理注册

- 客户端在登录成功后提交代理定义。
- 服务端先做字段、权限、端口/域名冲突和 P1 范围校验，再创建数据面资源。
- 成功响应只在资源可用后返回；失败不得留下半注册监听器或路由。
- 关闭代理后停止接收新流量，活动连接按生命周期排空。

## 7. 工作连接

1. 服务端根据待处理用户流量向已认证客户端请求工作连接。
2. 客户端建立新的同类连接传输，完成 wire 选择并声明其运行 ID 与鉴权材料。
3. 服务端验证工作连接属于当前控制会话，随后发送目标代理与源/目标摘要。
4. 双方完成可选加密、压缩或限速包装后进入透明转发。
5. 无效运行 ID、过期会话、重复绑定、未知代理或超时连接必须拒绝并释放资源。

工作连接池必须有上限和回收策略。任何网络 IO、SQLite 或通知调用不得在持有全局会话锁时执行。

## 8. 访客与 NAT 时序

### 8.1 STCP

访客连接提交目标代理、运行身份、共享密钥派生的鉴权材料与时间窗口。服务端验证目标存在、访客获准且未重放后，将访客连接与客户端工作连接配对。失败不得暴露目标是否存在以外的敏感配置。

### 8.2 XTCP

1. 访客与客户端分别向服务端报告候选地址和事务标识。
2. 服务端验证代理权限并协调双方获得匹配的会话材料。
3. 双方按独立实现的探测策略尝试直连并报告结果。
4. 成功后数据优先走点对点通道；失败行为必须可观察且释放临时资源。

P1 的 NAT 行为以黑盒互操作和真实网络验收为准，不复制参考实现的策略表。SUDP 留到 P2。

## 9. 代理与传输兼容矩阵

下表表示 P1 必须纳入测试的支持范围；“支持”不代表当前已经交付。

| 代理类型 | TCP | KCP | QUIC | WebSocket | WSS |
|---|---|---|---|---|---|
| TCP | 支持 | 支持 | 支持 | 支持 | 支持 |
| UDP | 支持 | 支持 | 支持 | 支持 | 支持 |
| HTTP | 支持 | 支持 | 支持 | 支持 | 支持 |
| HTTPS 透传 | 支持 | 支持 | 支持 | 支持 | 支持 |
| STCP | 支持 | 支持 | 支持 | 支持 | 支持 |
| XTCP | 支持 | 支持 | 支持 | 支持 | 支持 |

矩阵测试采用分层策略：每种传输先通过 wire/会话基础测试；每种代理通过代表性传输的完整语义测试；关键组合和全部声明组合通过自动化或真实互操作抽样门禁。XTCP 还必须进行用户确认的真实 NAT 环境验收。

## 10. HTTP 与 HTTPS 语义

- HTTP 代理可路由主机、路径和基础认证等 P1 已支持参数，并允许逐代理开启正文采集。
- HTTPS P1 为 TLS 透传，不终止 TLS、不解密、不宣称可读取正文。
- P2 才允许 JRP 明确终止 TLS 后采集其 HTTP 语义；届时必须新增 ADR/spec 和证书治理。
- 采集能力属于 jrps 适配器，不进入协议消息或 Core 的 SQLite 依赖。

## 11. 异常与兼容原则

- 未知 JSON 字段：在不影响安全与状态机的前提下忽略。
- 未知消息类型、非法帧类型、非零未知 flags：拒绝当前连接。
- 超限帧/消息、负长度等不可能值、截断输入：立即停止解析并释放资源。
- 非法状态迁移：拒绝消息，不得补猜前置状态。
- 鉴权失败：返回稳定类别，不回显 token、签名、完整时间材料或内部校验细节。
- 写入部分成功、对端半关闭、超时和取消：保证 goroutine、连接、缓冲区和临时状态被回收。
- 新字段/新消息只能在兼容矩阵和测试证明旧端可安全忽略或明确拒绝后加入。

## 12. 黑盒验收

- 使用固定基线官方 frpc 分别强制 wire v1、wire v2 连接 JRP jrps。
- 覆盖登录成功/失败、心跳超时、代理注册冲突、工作连接绑定、访客鉴权和 NAT 结果。
- 覆盖 FR-05a/05b/05c 连接传输与 FR-06a/06b 代理类型的矩阵。
- 生成 JRP 自有黄金帧和畸形输入，不复制参考测试数据结构或错误文案。
- 对吞吐、延迟、内存、连接泄漏和并发竞态设门禁。
- 真实 KCP/QUIC/WS/WSS、STCP/XTCP 和 NAT 环境结果由用户确认；测试全绿不能替代实机互操作。
